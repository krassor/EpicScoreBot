# gantt-schedule-recalc-locking Specification

## Purpose

Гарантирует, что пересчёт расписания конвейерного планировщика одной команды (даты эпиков/историй/ролевых задач) никогда не выполняется двумя конкурентными запросами одновременно — устраняя источник несогласованных дат при почти одновременных reorder-действиях (drag на графике, модалка «Порядок…», смена процента выполнения).

## Requirements

### Requirement: Пересчёт расписания команды сериализуется
Система SHALL гарантировать, что для одной и той же команды в любой момент времени выполняется не более одного пересчёта расписания (`RecalculateTeamSchedule`). Если новый запрос на пересчёт расписания этой команды поступает, пока предыдущий ещё выполняется, он SHALL дождаться завершения предыдущего перед тем, как начать собственный пересчёт (а не выполняться параллельно с ним).

#### Scenario: Два reorder-действия для одной команды подряд
- **WHEN** два действия, вызывающие пересчёт расписания одной и той же команды (например, drag эпика на графике и сохранение через модалку «Порядок…»), инициируются почти одновременно
- **THEN** второй пересчёт начинает читать данные только после того, как первый полностью завершил все свои изменения дат — оба пересчёта видят согласованное, а не частично изменённое состояние

#### Scenario: Пересчёты разных команд не блокируют друг друга
- **WHEN** пересчёт расписания инициируется одновременно для двух разных команд
- **THEN** они выполняются независимо, без ожидания друг друга

#### Scenario: Итоговое расписание после серии конкурентных запросов согласовано
- **WHEN** для одной команды подряд/почти одновременно инициируется несколько reorder-действий
- **THEN** после того как все они завершились, итоговое расписание команды полностью соответствует финальному состоянию очереди (`sort_order`) эпиков/историй — без пересекающихся по датам задач одной роли и без нарушения порядка эпиков, как если бы пересчёты выполнялись строго последовательно
