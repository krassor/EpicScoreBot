## Purpose

Позволяет superadmin назначать конкретным пользователям права
администратора для отдельных команд (many-to-many), храня привязку в БД,
и ограничивает действия команды-администратора рамками его команд.

## Requirements

### Requirement: Назначение team-admin
Только пользователь с ролью superadmin SHALL иметь возможность назначить
существующего зарегистрированного пользователя администратором одной или
нескольких команд. У одного пользователя MUST быть возможность быть
team-admin нескольких команд одновременно; у одной команды MUST быть
возможность иметь несколько team-admin одновременно.

#### Scenario: Superadmin назначает пользователя администратором команды
- **WHEN** superadmin выбирает команду и уже зарегистрированного
  пользователя и подтверждает назначение
- **THEN** пользователь становится team-admin выбранной команды и
  получает доступ к admin-функциям в рамках этой команды

#### Scenario: Один пользователь администрирует несколько команд
- **WHEN** superadmin назначает пользователя, уже являющегося team-admin
  команды A, администратором команды B
- **THEN** пользователь остаётся team-admin команды A и дополнительно
  становится team-admin команды B

#### Scenario: У команды несколько администраторов
- **WHEN** superadmin назначает второго пользователя team-admin команды,
  у которой уже есть team-admin
- **THEN** оба пользователя являются team-admin этой команды

#### Scenario: Не-superadmin пытается назначить team-admin
- **WHEN** пользователь без роли superadmin пытается назначить кого-либо
  team-admin (через Telegram-бот или веб-панель)
- **THEN** система отклоняет действие и не создаёт привязку

### Requirement: Снятие team-admin
Только superadmin SHALL иметь возможность снять привязку team-admin у
пользователя для конкретной команды, не затрагивая его привязки к другим
командам.

#### Scenario: Superadmin снимает администратора с одной из его команд
- **WHEN** superadmin снимает у пользователя, являющегося team-admin
  команд A и B, привязку к команде A
- **THEN** пользователь перестаёт быть team-admin команды A, но остаётся
  team-admin команды B

#### Scenario: Admin теряет доступ после снятия последней команды
- **WHEN** superadmin снимает у пользователя единственную привязку
  team-admin
- **THEN** пользователь перестаёт иметь права admin в системе (доступны
  только права обычного участника)

### Requirement: Доступ team-admin ограничен его командами
Пользователь с правами team-admin SHALL иметь доступ к
административным действиям (просмотр и редактирование пользователей,
эпиков, историй, рисков, простановка/переопределение оценок) только для
команд, в которых он назначен team-admin. Superadmin SHALL сохранять
полный доступ ко всем командам независимо от привязок в `team_admins`.

#### Scenario: Team-admin видит и редактирует эпики своей команды
- **WHEN** team-admin команды A запрашивает список эпиков или
  редактирует эпик, принадлежащий команде A
- **THEN** запрос выполняется успешно

#### Scenario: Team-admin не может управлять чужой командой
- **WHEN** team-admin команды A пытается создать/отредактировать эпик,
  назначить пользователя или переопределить оценку для команды B, в
  которой он не является team-admin
- **THEN** система отклоняет действие с ошибкой доступа и не вносит
  изменений

#### Scenario: Team-admin не видит пользователей чужой команды в
  административном списке
- **WHEN** team-admin команды A запрашивает список пользователей через
  административный интерфейс
- **THEN** в списке присутствуют только пользователи команд, в которых он
  назначен team-admin

#### Scenario: Superadmin не ограничен привязками team_admins
- **WHEN** superadmin, не имеющий ни одной записи в `team_admins`,
  выполняет административное действие над произвольной командой
- **THEN** запрос выполняется успешно независимо от привязок team-admin

### Requirement: Управление привязками через Telegram-бота
Superadmin SHALL иметь возможность назначать и снимать team-admin через
команды Telegram-бота с выбором команды и пользователя из списков
существующих команд/пользователей (без ввода произвольного текста
username).

#### Scenario: Назначение через бота
- **WHEN** superadmin вызывает команду назначения администратора в боте,
  выбирает команду из предложенного списка и пользователя из списка
  зарегистрированных участников
- **THEN** бот подтверждает назначение и пользователь становится
  team-admin выбранной команды

#### Scenario: Снятие через бота
- **WHEN** superadmin вызывает команду снятия администратора в боте и
  выбирает команду и одного из её текущих team-admin из предложенного
  списка
- **THEN** бот подтверждает снятие и пользователь перестаёт быть
  team-admin выбранной команды

### Requirement: Управление привязками через веб-панель
Superadmin SHALL иметь возможность просматривать список team-admin
выбранной команды, назначать и снимать team-admin через веб-панель
администрирования. Раздел управления team-admin SHALL быть недоступен
пользователям без роли superadmin.

#### Scenario: Superadmin просматривает список администраторов команды
- **WHEN** superadmin открывает раздел управления team-admin и выбирает
  команду
- **THEN** веб-панель отображает всех текущих team-admin этой команды

#### Scenario: Не-superadmin не видит раздел управления team-admin
- **WHEN** пользователь с ролью admin (не superadmin) открывает
  веб-панель администрирования
- **THEN** раздел управления team-admin не отображается и недоступен
