## Why

Сейчас на панели скоринга стори переопределить оценку можно только двумя способами: точечно за каждого участника («Изменить» в таблице «Оценки участников») или сразу для всей стори целиком («Переопределить» рядом с финальной оценкой). Когда нужно скорректировать оценку сразу по всей роли (например, «BE разработчик» — 10 чд для всех, независимо от того, сколько участников этой роли голосовало), пользователю приходится вручную менять оценку каждого участника этой роли по отдельности, что неудобно при количестве участников больше одного. Также при переопределении финальной оценки стори нет быстрого способа проверить/подставить значение, посчитанное по стандартной формуле (сумма риск-скорректированных оценок ролей, как в отчёте) — если переопределение введено ошибочно, вернуться к «правильному» числу можно только вручную пересчитав его в уме.

## What Changes

- Новая возможность переопределить агрегированную оценку роли целиком: в строке таблицы «Оценки по ролям» добавляется поле ввода и кнопка «Переопределить», которые напрямую задают значение оценки роли для этой стори — без изменения оценок отдельных участников.
- Новый backend-эндпоинт `POST /api/gantt/admin/scores/role` (admin-only, team-scoped, по аналогии с существующим `POST /api/gantt/admin/scores/final`) — принимает `{epic_id, role_id, score}`, требует, чтобы стори уже была в статусе `SCORED`, и напрямую перезаписывает `epic_role_scores.weighted_avg` для этой роли (upsert, без побочного пересчёта финальной оценки стори или родительского эпика — переопределение роли и переопределение финальной оценки остаются двумя независимыми явными действиями администратора).
- Новый backend-эндпоинт предпросмотра `GET /api/gantt/admin/scores/{epic_id}/recalc-preview` (admin-only, team-scoped) — считает финальную оценку стори по стандартной формуле (`Σ(oценка_роли) × Π(коэффициент_риска)`, округление до целого) на основе **текущих** сохранённых оценок по ролям (включая уже применённые переопределения ролей) и рисков стори, без сохранения результата.
- Рядом с существующей кнопкой «Переопределить» (финальная оценка стори) добавляется кнопка «Пересчитать по формуле» — заполняет поле ввода результатом предпросмотра, не сохраняя его автоматически; сохранение по-прежнему требует явного нажатия «Переопределить».

## Capabilities

### New Capabilities
- `role-score-override`: переопределение агрегированной оценки роли для стори администратором, и пересчёт-предпросмотр финальной оценки по стандартной формуле как вспомогательное действие рядом с переопределением финальной оценки стори.

### Modified Capabilities
(нет — существующее переопределение финальной оценки стори и оценок участников не меняется, новая кнопка «Пересчитать по формуле» только заполняет уже существующее поле ввода)

## Impact

- **Backend**: `internal/scoring/scoring.go` (новый метод `SetManualRoleScore`, аналогичный `SetManualFinalScore`; новый метод/хелпер расчёта предпросмотра финальной оценки на основе сохранённых `epic_role_scores` + рисков), `internal/transport/httpServer/handlers/admin_scores.go` (два новых хендлера), `internal/transport/httpServer/routers/routers.go` (два новых роута в существующей admin-only группе). Изменений схемы БД не требуется — `epic_role_scores` уже поддерживает upsert по `(epic_id, role_id)`.
- **Frontend**: `web/gantt/js/scoring-panel.js` — `renderRoleScoresTableRows` (добавить поле ввода + кнопку в строку роли, только для admin), блок переопределения финальной оценки (добавить кнопку «Пересчитать по формуле» и обработчик).
- Затрагивает и backend, и frontend — новые эндпоинты, требуется согласование перед реализацией (`/opsx:apply`).
