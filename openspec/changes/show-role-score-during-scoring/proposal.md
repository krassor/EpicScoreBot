## Why

Администратор проставляет экспертную оценку через «Оценить всей ролью», оценки участников этой роли сохраняются корректно (видны в таблице «Оценки участников» как `5 чд`), но строка самой роли в таблице «Оценки по ролям» продолжает показывать прочерк — и после полной перезагрузки страницы тоже. Из-за этого администратор не видит результата собственного действия и не понимает, какие роли уже закрыты, а какие ещё ждут голосов: единственный признак прогресса — глазами сверять список участников со списком ролей.

Это не баг обновления данных, а конструктивный пробел:

- `renderRoleScoresTableRowsScoring()` (`web/gantt/js/scoring-panel.js:604`) в статусе `SCORING` **безусловно** рисует `—` в колонке «Оценка (чд)», не читая оценки вообще;
- бэкенд заполняет `epic_role_scores` только внутри `TryCompleteEpicScoring` (`internal/scoring/scoring.go:186`) и только когда проголосовала **вся команда** — при `epicScoreCount < teamMembers` происходит ранний выход, поэтому `GET /epics/{id}/role-scores` в статусе `SCORING` всегда отдаёт пустой список (это уже зафиксировано в комментарии к `buildEvaluatingRolesForScoring`).

## What Changes

- В таблице «Оценки по ролям», пока стори в статусе `SCORING`, колонка «Оценка (чд)» для роли, по которой проголосовали **все** участники команды с этой ролью, SHALL показывать средневзвешенную оценку этой роли вместо прочерка. Для не полностью покрытой роли остаётся прочерк.
- Рядом с прочерком у не покрытой полностью роли показывается индикатор покрытия вида `(1/2)` — сколько участников роли уже проголосовало из скольких ожидаемых. Полностью покрытая роль показывает только значение оценки, без индикатора.
- Значение считается **на фронтенде** из уже загруженного ответа `GET /epics/{epic_id}/scores`: он уже отдаёт `user.weight` и `role` по каждому голосу и полный список `members` с `weight`/`role_id`. Новых запросов, новых полей ответа и изменений бэкенда не требуется.
- Формула повторяет `scoring.CalculateEpicRoleAvg`: `Σ(score × weight) / Σ(weight)` по голосам этой роли — чтобы показанное во время `SCORING` значение совпадало с тем, что бэкенд позже сохранит в `epic_role_scores`, и цифра не менялась при переходе стори в `SCORED`.

**Принятые допущения** (уточнить, если не совпадают с ожиданием):

- Колонка «Действие» не меняется: поле ввода и кнопка «Оценить всей ролью» остаются у **всех** ролей, включая полностью покрытые, — чтобы администратор мог исправить ошибочно проставленную экспертную оценку, не дожидаясь `SCORED`.
- Формат вывода значения — тот же, что в таблице для статуса `SCORED` (`<значение> чд`), чтобы при переходе в `SCORED` внешний вид ячейки не менялся. Улучшение форматирования дробных значений — вне объёма этого change.
- Роль без единого участника в команде считается непокрытой и показывает прочерк (проголосовать за неё некому).

## Capabilities

### New Capabilities

_нет_

### Modified Capabilities

- `role-expert-vote`: добавляется требование к отображению — таблица «Оценки по ролям» показывает не только список оцениваемых ролей во время `SCORING` (это требование уже есть), но и посчитанную оценку для роли, набравшей все ожидаемые голоса, плюс индикатор покрытия для остальных.

  Базовая спецификация этой capability пока лежит в незаархивированном change `add-role-expert-vote` (`openspec/changes/add-role-expert-vote/specs/role-expert-vote/spec.md`), а не в `openspec/specs/`. Дельта оформлена как `## ADDED Requirements` и применима в обоих случаях; порядок архивации — `add-role-expert-vote`, затем этот change.

## Impact

- **Frontend** (единственная затронутая область, субагент `frontend`) — `web/gantt/js/scoring-panel.js`:
  - `buildEvaluatingRolesForScoring()` — обогащается данными голосов (средневзвешенная + покрытие);
  - `renderRoleScoresTableRowsScoring()` / `renderRoleScoresTableHtmlScoring()` — рендер значения вместо безусловного прочерка;
  - `refreshRoleScoresTable()` — точечный рефреш таблицы сейчас перезапрашивает только `role-scores` и не обновляет `selectedStoryScores`, от которого теперь зависит содержимое строк; это нужно учесть.
- **Backend** — без изменений: ни `internal/scoring/`, ни `internal/repositories/`, ни хендлеры. Слои transport/services/repositories не затрагиваются.
- **API-контракты** — без изменений: `GET /epics/{epic_id}/scores` и `GET /epics/{epic_id}/role-scores` остаются как есть; формат ошибок не затрагивается.
- **БД** — без изменений: ни схемы, ни миграций.
- **QA** (субагент `qa`) — проверка сценариев отображения: роль покрыта полностью / частично / без голосов; совпадение показанного во время `SCORING` значения с сохранённым после перехода в `SCORED`.
- **DevOps** — не затрагивается.
- Связанные changes: `add-role-expert-vote` (вводит саму кнопку «Оценить всей ролью» и capability `role-expert-vote`) и `fix-stale-story-status-refresh` (чинит устаревание `selectedStory` в `loadEpicData()`) — оба независимы от этого change и им не конфликтуют.
