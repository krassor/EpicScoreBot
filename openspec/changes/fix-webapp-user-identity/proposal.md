## Why

Выгрузка диаграммы Ганта картинкой на проде всегда завершается `409 BOT_CHAT_NOT_STARTED` с подсказкой «откройте личный чат с ботом» — даже у пользователя, у которого этот чат открыт. Причина не в чате: веб-сессия и справочник пользователей опознают человека по разным ключам, и запрос получателя в БД не находит никого.

`middleware.UserSession.TelegramID` — это **числовой** Telegram user ID (`telegram_auth.go:175`, `gantt.go:1224`), а колонка `users.telegram_id` хранит **@username**: по нему бот заводит (`handlers_admin.go:72`), ищет (`handlers.go:98`, `handlers_epic.go:155`) пользователей, и так же его трактует фронтенд (`scoring-panel.js:975`). Поиск числового ID в колонке с username не даёт совпадений никогда.

Экспорт картинки — лишь самое заметное проявление. Тот же рассинхрон действует во всём HTTP-слое: роль `member`, `team-admin` и выбор списка команд резолвят пользователя по тому же неверному ключу, поэтому веб-панель сейчас по-настоящему работает только у superadmin — он определяется по `Username` из конфига, минуя БД.

## What Changes

- **Получатель картинки берётся из сессии напрямую, без БД.** В Telegram ID личного чата совпадает с ID пользователя, поэтому `ExportGanttImage` отправляет документ на числовой `session.TelegramID`, не резолвя пользователя и не читая `users.chat_id`. Единственным источником `BOT_CHAT_NOT_STARTED` остаётся реальный `403` от Telegram — подсказка «откройте чат» наконец называет настоящую причину. Адресат по-прежнему берётся только из сессии, никогда из тела запроса.
- **Вводится единый ключ опознания веб-сессии в справочнике пользователей.** Сессия получает явный «ключ справочника», производный от `Username` (нормализация: нижний регистр, отброшенный ведущий `@`), и все обращения HTTP-слоя к справочнику идут через него вместо `session.TelegramID`.
- **Сравнение в БД становится устойчивым к регистру и ведущему `@`.** `users.telegram_id` заполнялся разными путями (бот срезает `@`, CSV-импорт — нет), поэтому поиск по ключу сравнивает нормализованные значения.
- **Пользователь без @username получает внятный отказ**, а не «доступ запрещён» без объяснения: веб ведёт себя так же, как бот, который уже просит задать username.
- Схема БД не меняется: миграции нет, данные не трогаем, `users.telegram_id` остаётся справочным ключом по @username.
- Не входит в объём: перевод справочника на числовой Telegram ID и автозаполнение `users.chat_id` из веб-сессии — вынесено в «Дальнейшие шаги» design.md.

## Capabilities

### New Capabilities
- `webapp-user-identity`: как веб-сессия Telegram опознаётся в справочнике пользователей — какой ключ канонический, как ведёт себя система при отсутствии совпадения и при отсутствии @username. Сегодня это поведение не описано ни одной спекой, чем и объясняется незамеченный рассинхрон.

### Modified Capabilities
- `gantt-chart-image-export`: доставка картинки не зависит от того, заведён ли пользователь в справочнике и известен ли его `chat_id`; подсказка «откройте чат с ботом» выдаётся только когда это действительно причина.

## Impact

- **Слои**: transport (middleware + handlers) и repositories. Слой services не затрагивается.
- **Backend** (субагент `backend`):
  - `internal/transport/httpServer/middleware/telegram_auth.go` — ключ справочника в `UserSession`;
  - `internal/transport/httpServer/middleware/role_auth.go` — резолвинг роли `member` и team-admin;
  - `internal/transport/httpServer/handlers/gantt_export.go` — адресат из сессии напрямую, без БД;
  - остальные 40 обращений `session.TelegramID` к справочнику: `handlers/gantt.go`, `scoring.go`, `admin_scores.go`, `admin.go`, `stories.go`, `team_admin.go`, `notify.go`, `schedule_settings.go`;
  - `internal/repositories/user.go`, `team.go`, `team_admin_auth.go` — нормализованное сравнение ключа.
- **API**: изменений в контрактах эндпоинтов нет. Коды ошибок `BOT_CHAT_NOT_STARTED`, `TELEGRAM_SEND_FAILED`, `NOTIFIER_UNAVAILABLE` сохраняются; меняется только то, при каких условиях они возникают. Формат `{ "error": { "code", "message" } }` не трогаем.
- **Frontend**: изменений не требуется — `GetProfile` продолжает отдавать те же поля, обработка кодов ошибок в `gantt-image-export.js` остаётся прежней.
- **QA** (субагент `qa`): тесты на резолвинг по нормализованному ключу, на экспорт без записи в справочнике, на отсутствие @username; проверка, что `gantt_export_test.go` больше не опирается на `FindUserByTelegramID`.
- **DevOps**: не затрагивается — ни миграций, ни изменений конфигурации.
- **Совместимость**: выданные ранее cookie `tg_sys_auth` (срок 7 дней) содержат оба поля — `telegram_id` и `username` — поэтому продолжают работать без перелогина.
- **Взаимодействие с незаархивированной заявкой** `export-gantt-chart-image`: её delta-спека ещё не синхронизирована в `openspec/specs/gantt-chart-image-export/`, поэтому наша delta добавляет требование, а не переписывает её формулировки.
