- [x] 2.7 Пересчитывать ширину при возврате на вкладку «Гант». `switchTab` (`app.js:449-471`) только переключает класс `.hidden` и перерисовки не делает, поэтому resize, произошедший на другой вкладке, до диаграммы не доходит: контейнер в тот момент скрыт и его ширина равна нулю. Подписаться на `activeTab` и применять пересчёт при переходе на «Гант». Добавленный объём сверх исходного плана — согласован с пользователем. Проверка: изменить размер окна, находясь на вкладке «Скоринг», вернуться на «Гант» — сетка соответствует новой ширине окна без переключения масштаба и перезагрузки.
- [x] 2.8 Починить сброс масштаба при применении ширины. `update_options(t)` делает `setup_options({...this.original_options, ...t})`, а `setup_options` пересобирает `this.options` из `original_options` — то есть `view_mode` откатывается на тот, что был передан в конструктор. Следом `update_options` зовёт `change_view_mode(void 0, true)`, где значение по умолчанию первого аргумента — уже откаченный `this.options.view_mode`. В результате при переключении на «Неделю»/«Месяц» сетка рисуется в дневном масштабе, но с шириной колонки, посчитанной для нового режима: масштаб визуально увеличивается вместо уменьшения, а видимое окно уезжает за пределы диапазона задач и бары пропадают. Передавать текущий масштаб вместе с шириной (`update_options({ column_width, view_mode })`); ветка `t.view_modes → view_mode = view_modes[0]` в `setup_options` при этом не срабатывает, т.к. приложение `view_modes` в конструктор не передаёт — проверить это фактически. Проверка: переключение День → Неделя → Месяц и обратно меняет цену деления шкалы (в шапке недели/месяцы, а не числа месяца), бары остаются на экране во всех трёх режимах, ширина колонки соответствует выбранному масштабу.

## 3. QA — ручная проверка

Автотестов в этой заявке нет: JS-раннера в проекте не существует, покрывать фронтенд тестами вне области (см. design.md, Risks). Все проверки ниже — ручные, по сценариям `specs/gantt-chart-viewport-fit/spec.md`.

- [x] 3.1 Пройти сценарии требования «Рабочая область занимает всю доступную ширину»: квартальный план в масштабе «Месяц» и узкий диапазон в масштабе «День». Проверка: в обоих случаях сетка занимает всю ширину, бары соответствуют своим датам на растянутой шкале.
- [x] 3.2 Пройти сценарии требования «Широкий диапазон сохраняет прокрутку»: годовой диапазон в масштабе «День» и диапазон на границе — чуть шире доступной области. Проверка: колонки штатной ширины, есть горизонтальная прокрутка, пустого поля не появляется.
- [x] 3.3 Пройти сценарии требований «Ширина пересчитывается при смене масштаба» и «при изменении размера окна»: все переключения День/Неделя/Месяц в обе стороны, разворачивание окна, сужение до появления прокрутки. Проверка: наблюдаемое поведение соответствует сценариям спеки.
- [x] 3.4 Пройти сценарии требования «Растягивание не ухудшает читаемость»: узкое окно (мобильный клиент) и диаграмма с завершёнными задачами, задачами без исполнителя и с недействующим закреплением при растянутой сетке. Проверка: колонки не уже штатных; подписи, факт-маркеры, стрелки зависимостей и индикация состояний исполнителя отображаются так же, как без растягивания.
