## Why

В панели скоринга эпика (веб-Gantt) нет способа удалить ошибочно созданный или более не нужный эпик — приходится оставлять «мусорные» эпики в списке команды. Backend-хендлер `DeleteEpic` уже существует (`internal/transport/httpServer/handlers/admin.go`), но не подключён к роутеру и недоступен ни из UI, ни по HTTP.

## What Changes

- Подключить существующий хендлер `GanttHandler.DeleteEpic` к роутеру: `DELETE /api/gantt/epics/{epic_id}`, доступ — только роль `superadmin` (аналогично группе `/admin/team-admins`).
- Переименовать параметр маршрута в хендлере `DeleteEpic` с `id` на `epic_id`, чтобы не конфликтовать с уже зарегистрированным `PUT /epics/{epic_id}` на том же узле роутера chi.
- В веб-панели скоринга (`web/gantt/js/scoring-panel.js`) добавить кнопку «🗑️ Удалить» рядом с кнопкой «✏️ Редактировать» в заголовке деталей эпика — видна только пользователям с ролью `superadmin`.
- По клику — кастомное модальное окно подтверждения удаления (в стиле существующих модалок редактирования: `.modal-overlay` + `.modal-content`), с явным предупреждением о безвозвратности и каскадном удалении историй/рисков/оценок эпика. Подтверждение вызывает `DELETE /api/gantt/epics/{epic_id}`.
- Удаление разрешено для эпика в любом статусе (`NEW`/`SCORING`/`SCORED`) — без дополнительных проверок на бэкенде сверх уже существующей логики `DeleteEpic`.
- После успешного удаления: эпик пропадает из списка эпиков команды, панель деталей возвращается в пустое состояние («Выберите эпик для оценки»), показывается toast об успехе.

## Capabilities

### New Capabilities

_нет_

### Modified Capabilities

- `epic-scoring-panel`: добавляется требование — кнопка удаления эпика (только `superadmin`) с модальным подтверждением и последующим удалением эпика через API.

## Impact

- **Backend** (`internal/transport/httpServer/routers/routers.go`, `internal/transport/httpServer/handlers/admin.go`): регистрация нового защищённого маршрута, точечное переименование параметра URL в существующем хендлере. Слой `services`/`repositories` не меняется — `Repository.DeleteEpic` уже реализован и полагается на `ON DELETE CASCADE` в схеме БД.
- **Frontend** (`web/gantt/js/scoring-panel.js`): новая кнопка в заголовке панели деталей эпика, новая модалка подтверждения, обновление списка эпиков и состояния панели после удаления.
- **API-контракт**: новый эндпоинт `DELETE /api/gantt/epics/{epic_id}`, формат ответа/ошибок — по стандарту проекта (`{ "status": "ok" }` при успехе, `{ "error": { "code", "message" } }` при ошибке — уже реализовано в хендлере).
- **QA**: нужны тесты на хендлер (права доступа superadmin/прочие роли, каскадное удаление) и, по возможности, проверка UI-сценария.
