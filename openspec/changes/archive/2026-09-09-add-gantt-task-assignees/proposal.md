## Why

Конвейерный планировщик считает **роль единственным ресурсом**: карта `roleFreeAt` (`internal/gantt/ganttService.go`) хранит по одной дате освобождения на роль, поэтому все BE-задачи команды выстраиваются в одну строго последовательную цепочку — даже если BE-разработчиков в команде трое. График показывает сроки, растянутые в разы против реальных, и по нему нельзя понять, кто именно делает задачу. Одновременно нет никакого способа сказать «эту задачу делает Иванов»: назначение отсутствует в модели как понятие.

## What Changes

- **Ресурсом становится человек, а не роль.** Планировщик ведёт календарь занятости по исполнителю (`assigneeFreeAt`), поэтому задачи одной роли из разных стори могут выполняться параллельно разными людьми. Пул исполнителей роли внутри команды берётся из `user_roles` × `user_teams`.
- **У каждой листовой (ролевой) задачи появляется исполнитель**, вычисляемый автоматически при пересчёте расписания и сохраняемый в `gantt_tasks.assignee_id`.
- **Автоматическое распределение** — жадное по фактической дате старта: задача достаётся тому из пула, кто может начать её раньше всех, а при равенстве — следующему по круговому обходу (round-robin). Обход детерминирован: при неизменных входных данных повторный пересчёт даёт то же самое распределение.
- **Ручное назначение исполнителя** через модалку деталей задачи имеет приоритет над автоматическим: закреплённая задача достаётся указанному человеку, даже если это отодвигает её старт. Возврат к автоматическому распределению — выбором пункта «Автоматически» (снятие закрепления).
- **Ручные назначения хранятся отдельно от диаграммы** — в новой таблице `task_assignments`, ключ `(epic_id, role_id)`, где `epic_id` — идентификатор стори (или самого эпика для legacy-эпиков без стори). Это делает их устойчивыми к перегенерации задач, которая удаляет и пересоздаёт все строки `gantt_tasks`.
- **Попутно чинится существующая потеря `start_offset_days`**: сейчас ручное смещение старта задачи молча сбрасывается в 0 при любой перегенерации (`generateTaskRowsForEpic` не переносит его в новые строки), что особенно заметно при массовой перегенерации квартала. Смещение переезжает в ту же таблицу пользовательского ввода `task_assignments` и переживает перегенерацию.
- **Роль без исполнителей в команде** (например, есть оценка по «Mobile разработчик», но мобильщиков в команде нет) планируется по-прежнему — роль сама себе ресурс, задача остаётся без исполнителя, генерация не блокируется.
- **Новый эндпоинт состава команды** `GET /api/gantt/teams/{id}/members` — источник списка кандидатов для выпадающего списка исполнителей. Существующий метод `GetRoleByUserID` для этого непригоден: он возвращает одну роль на пользователя, тогда как `user_roles` — связь M:N.
- **Исполнитель отображается в подписи задачи** на диаграмме. Это не косметика: до этого изменения два бара одной роли не могли пересекаться по времени конструктивно, а теперь пересекаются регулярно, и без имени исполнителя такие бары неразличимы.
- Загрузка человека считается **в границах одной команды**. Участник двух команд получает два независимых календаря — существующая семантика `RecalculateTeamSchedule` и per-team блокировки сохраняется.

## Capabilities

### New Capabilities
- `gantt-task-assignees`: назначение исполнителя на ролевую задачу Ганта (автоматическое распределение по пулу роли, ручное закрепление с приоритетом и возврат к автоматическому), параллельное планирование задач одной роли разными исполнителями, устойчивость пользовательского ввода (закрепление, смещение старта) к перегенерации задач, отображение исполнителя на диаграмме.

### Modified Capabilities
- `gantt-schedule-recalc-locking`: сценарий «Итоговое расписание после серии конкурентных запросов согласовано» сейчас требует отсутствия «пересекающихся по датам задач одной роли». После этого изменения такое пересечение — штатное поведение (разные исполнители одной роли работают параллельно). Требование сериализации пересчёта не меняется; корректируется только критерий согласованности итогового расписания — он формулируется через занятость исполнителя, а не роли.

## Impact

**Backend** (субагент `backend`):
- **Миграция** `internal/migrator/migrations/011_task_assignees.sql`: новая таблица `task_assignments (epic_id UUID FK epics, role_id UUID FK roles, user_id UUID NULL FK users, start_offset_days INT NOT NULL DEFAULT 0, PRIMARY KEY (epic_id, role_id))`; новая колонка `gantt_tasks.assignee_id UUID NULL FK users`; перенос данных из `gantt_tasks.start_offset_days` в новую таблицу. Исходная колонка в этой миграции **не удаляется** — мигратор проекта forward-only, down-миграций нет, поэтому удаление выносится в отдельную миграцию после проверки на проде (см. design.md).
- `repositories`: `internal/repositories/gantt.go` — CRUD закреплений и смещений, чтение назначений пачкой по команде, запись `assignee_id`. `internal/repositories/user.go` — уже существующий `GetUsersByTeamIDAndRoleID` переиспользуется без изменений.
- `services`: `internal/gantt/ganttService.go` — замена `roleFreeAt` на календарь по исполнителю с сохранением ролевого календаря как запасного пути для пустого пула; жадный выбор с round-robin тай-брейком; учёт закреплений; чтение исполнителя замороженных задач вместо пересчёта; `generateTaskRowsForEpic` перестаёт терять пользовательский ввод. `internal/gantt/interfaces.go` — новые методы репозитория в контракте.
- `transport`: `internal/transport/httpServer/handlers/gantt.go` — обработчик назначения исполнителя, обработчик состава команды, поля `assignee_id`/`assignee_name`/`assignee_is_manual` в `ganttTaskResp`. `internal/transport/httpServer/handlers/interfaces.go` — новые методы сервиса. `internal/transport/httpServer/routers/routers.go` — маршруты `PUT /tasks/{id}/assignee` и `GET /teams/{id}/members` в существующей аутентифицированной группе.
- `domain`: `internal/models/domain/gantt.go` — поле `AssigneeID`, перенос семантики `StartOffsetDays`.
- Формат ошибок API не меняется. Новые зависимости не добавляются.

**Frontend** (субагент `frontend`, постановка — субагент `ux`):
- `web/gantt/index.html` — выпадающий список исполнителя в модалке деталей задачи с пунктом «Автоматически».
- `web/gantt/js/gantt-renderer.js` — подпись исполнителя в имени задачи, обработчик смены исполнителя, индикация задач без исполнителя и закреплений на выбывшего из пула человека.
- `web/gantt/js/api.js`, `web/gantt/js/app.js` — вызовы новых эндпоинтов, загрузка состава команды.
- `web/gantt/css/` — стили индикации.

**QA** (субагент `qa`):
- `internal/gantt/` — детерминизм повторного пересчёта, параллельное распределение по стори, приоритет закрепления над автоматом, пустой пул роли, неизменность исполнителя замороженной задачи, сохранение закреплений и смещений при перегенерации квартала.
- `internal/transport/httpServer/handlers/` — новые обработчики.

**DevOps**: не затрагивается (миграции применяются существующим механизмом `internal/migrator`).
