## Purpose

Автоматизирует сборку, версионирование, публикацию Docker-образа
приложения в Docker Hub по git-тегу релиза и последующее обновление
приложения на продакшн-VPS до опубликованной версии, с проверкой
работоспособности и откатом при неудаче.

## ADDED Requirements

### Requirement: Сборка и публикация образа по тегу релиза
При push git-тега вида `vX.Y.Z` в репозиторий система SHALL собрать
Docker-образ приложения из `Dockerfile` и опубликовать его в Docker Hub
с двумя тегами: точной версией `X.Y.Z` и `latest`. Push тега, не
соответствующего формату `vX.Y.Z`, SHALL не запускать сборку и
публикацию образа.

#### Scenario: Push корректного тега версии
- **WHEN** в репозиторий запушен git-тег `v1.4.0`
- **THEN** запускается сборка образа и в Docker Hub публикуются образы с
  тегами `1.4.0` и `latest`

#### Scenario: Push тега не в формате версии
- **WHEN** в репозиторий запушен тег, не соответствующий шаблону
  `vX.Y.Z` (например, произвольная метка)
- **THEN** пайплайн сборки и публикации образа не запускается

#### Scenario: Ошибка сборки образа
- **WHEN** сборка Docker-образа завершается ошибкой (например, код не
  компилируется)
- **THEN** образ не публикуется в Docker Hub и последующий деплой на VPS
  не запускается

### Requirement: Автоматическое обновление VPS после публикации образа
После успешной публикации образа конкретной версии в Docker Hub система
SHALL автоматически подключиться к продакшн-VPS по SSH и обновить
запущенный контейнер приложения до этой опубликованной версии, без
дополнительного ручного подтверждения.

#### Scenario: Успешный деплой опубликованной версии
- **WHEN** образ версии `1.4.0` успешно опубликован в Docker Hub
- **THEN** система подключается к VPS, обновляет контейнер приложения на
  образ версии `1.4.0` и запускает его

#### Scenario: Деплой не запускается при неудачной публикации
- **WHEN** публикация образа в Docker Hub завершилась ошибкой
- **THEN** обновление контейнера на VPS не выполняется

### Requirement: Проверка работоспособности и откат после деплоя
После обновления контейнера приложения на VPS система SHALL проверить
его работоспособность через healthcheck-эндпоинт приложения в течение
ограниченного числа попыток. Если работоспособность не подтверждена,
система SHALL автоматически откатить контейнер на предыдущую
работавшую версию образа.

#### Scenario: Новая версия проходит healthcheck
- **WHEN** после обновления контейнер новой версии отвечает на
  healthcheck-эндпоинте успешным статусом в течение отведённого числа
  попыток
- **THEN** деплой считается успешным, откат не выполняется

#### Scenario: Новая версия не проходит healthcheck
- **WHEN** после обновления контейнер новой версии не отвечает успешным
  статусом на healthcheck-эндпоинте ни за одну из отведённых попыток
- **THEN** система автоматически возвращает контейнер на предыдущую
  версию образа, работавшую до деплоя

#### Scenario: Нет предыдущей версии для отката
- **WHEN** новая версия не проходит healthcheck при самом первом деплое
  по этой схеме (предыдущей версии образа не существует)
- **THEN** система сообщает об ошибке деплоя, не пытаясь откатиться на
  несуществующую версию
