## Why

Сейчас образ приложения собирается вручную на самом VPS (`run_docker_build.sh`,
`scripts/deploy/deploy.sh` — оба делают `git pull` + `docker compose build`
прямо на сервере). Нет версионированного артефакта образа и
автоматической сборки/публикации при релизе — каждое обновление требует
ручных действий на сервере, отсутствует история версий образа и
возможность быстро откатиться на конкретную предыдущую версию.

## What Changes

- Новый workflow `.github/workflows/release.yml`, запускаемый по push
  git-тега вида `vX.Y.Z`:
  - Джоба **build-and-push**: сборка Docker-образа из `Dockerfile` и
    публикация в Docker Hub с тегами `X.Y.Z` и `latest`.
  - Джоба **deploy**: выполняется только после успешного
    build-and-push, подключается по SSH к VPS и обновляет запущенный
    контейнер приложения на опубликованный образ конкретной версии
    (`X.Y.Z`), с healthcheck-проверкой и откатом на предыдущий образ при
    неудаче.
- **BREAKING** (для процесса деплоя, не для приложения): модель деплоя
  на VPS меняется с "собрать образ из исходников на сервере" на "скачать
  готовый образ из Docker Hub" — требует одноразового ручного изменения
  `docker-compose.yml` на самом VPS (файл не в git, см. design.md) —
  сервис приложения должен ссылаться на `image: <repo>:${VERSION}` вместо
  `build: context: .`.
- Существующие `run_docker_build.sh` и `scripts/deploy/deploy.sh`
  (build-на-сервере) не удаляются — остаются как ручной fallback-путь
  деплоя, если понадобится собрать образ прямо на VPS в обход
  Docker Hub.

## Capabilities

### New Capabilities
- `image-release-pipeline`: автоматическая сборка, версионирование и
  публикация Docker-образа приложения в Docker Hub по git-тегу, с
  последующим автоматическим обновлением приложения на VPS до
  опубликованной версии.

### Modified Capabilities
(нет существующих спек, связанных с CI/CD)

## Impact

- **devops**:
  - Новый `.github/workflows/release.yml`.
  - Новый/адаптированный скрипт деплоя по образу (например
    `scripts/deploy/deploy_image.sh`) — по аналогии с уже существующим
    `scripts/deploy/deploy.sh` (healthcheck-цикл, откат), но
    оперирующий тегом образа вместо git-коммита.
  - Требуемые GitHub Secrets (заводятся пользователем вручную в
    настройках репозитория, не частью этой задачи): `DOCKERHUB_USERNAME`,
    `DOCKERHUB_TOKEN`, `VPS_HOST`, `VPS_USER`, `VPS_SSH_KEY`.
  - Одноразовое ручное изменение `docker-compose.yml` на VPS (файл не
    версионируется в git — см. design.md), выполняется пользователем/DevOps
    вне этой задачи по инструкции, которую задача должна предоставить.
- Backend/frontend/qa — не затронуты (Dockerfile и структура сборки не
  меняются).
- Формат ошибок API не относится к этой задаче.
