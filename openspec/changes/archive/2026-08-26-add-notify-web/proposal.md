## Why

Напоминание непроголосовавшим участникам эпика сейчас доступно только
через Telegram-команду `/epicnotify`. Администратор, работающий со
страницей скоринга в веб-панели, вынужден переключаться в бот, чтобы
разослать напоминания — неудобно и разрывает рабочий процесс на странице
скоринга эпика.

## What Changes

- Кнопка "Напомнить непроголосовавшим" на странице скоринга рядом с
  эпиком (веб-панель Gantt), видимая только admin/superadmin и только
  пока эпик в статусе SCORING (как и в боте — команда фильтрует эпики по
  этому статусу).
- Новый защищённый HTTP-эндпоинт `POST /api/gantt/epics/notify`
  (body `{epic_id}`), доступный только team-admin команды эпика или
  superadmin, рассылающий те же напоминания, что и `/epicnotify` в боте
  (идентичный текст сообщения и критерий "кто ещё не проголосовал").
- Бизнес-правило "кто ещё не проголосовал по эпику + текст напоминания"
  выносится из `internal/telegram/admin_callbacks.go` в новый
  нейтральный пакет (не зависящий ни от Telegram-транспорта, ни от HTTP)
  и переиспользуется обоими вызывающими путями — без дублирования логики
  между ботом и веб-панелью (см. design.md).
- Поведение существующей команды `/epicnotify` в боте не меняется
  (рефакторинг внутренней реализации, наблюдаемый результат для
  пользователя бота идентичен).

## Capabilities

### New Capabilities
- `epic-scoring-reminders`: ручная рассылка напоминаний непроголосовавшим
  участникам эпика администратором — из Telegram-бота и из веб-панели,
  единый критерий "кто ещё не проголосовал" и единый текст напоминания.

### Modified Capabilities
(нет существующих спек, покрывающих команду `/epicnotify` — вся задача
описывается новой capability `epic-scoring-reminders`)

## Impact

- **backend** (слои: новый нейтральный пакет бизнес-правила →
  services/telegram/transport):
  - Новый пакет (например `internal/notify`): извлечённая из
    `admin_callbacks.go` логика вычисления списка "кому напомнить" и
    текста напоминания + вспомогательная функция рассылки поверх
    функции отправки, общая для бота и HTTP.
  - `internal/telegram/admin_callbacks.go`, `telegramBot.go`: рефакторинг
    `sendEpicNotifications` на использование нового пакета; добавление
    метода отправки прямого сообщения на `*Bot`, используемого также HTTP-слоем.
  - `internal/transport/httpServer/handlers/interfaces.go`: расширение
    `Repository` двумя уже существующими в БД-репозитории методами
    (`HasUserScoredEpic`, `GetUnscoredRisksByUser`); новый интерфейс для
    отправки Telegram-сообщения, реализуемый `*telegram.Bot`.
  - `internal/transport/httpServer/handlers/`: новый хендлер
    `POST /epics/notify` с team-scoped проверкой admin (по образцу
    `AdminSubmitEpicScore`) и валидацией статуса эпика (SCORING).
  - `internal/transport/httpServer/routers.go`: роут — в защищённой
    admin-группе (`RoleAuth(..., "admin")`), а не в общей группе (в
    отличие от соседнего `/epics/start`, который сейчас не защищён
    сервером — см. design.md, это осознанно не трогаем).
  - `app/main.go`: `tgBot` передаётся в `handlers.NewGanttHandler(...)`
    как новая зависимость для отправки сообщений.
- **frontend** (`web/gantt/`): `web/gantt/js/scoring-panel.js` — кнопка в
  заголовке карточки эпика (`renderDetails`), обработчик в `bindEvents`,
  вызов нового эндпоинта, отображение результата (`showToast`).
- **qa**: тесты на новый хендлер (happy path, 403 для не-admin/team-admin
  чужой команды, 400 для эпика не в статусе SCORING) и на новый пакет
  бизнес-правила (кто считается непроголосовавшим).
- Формат ошибок API не меняется.
