## Why

Список «Эпики команды» (левая колонка панели скоринга) при большом числе эпиков команды показывает их все подряд без возможности отфильтровать по кварталу планирования, году или типу эпика — приходится прокручивать весь список, чтобы найти нужные эпики конкретного квартала/года/типа.

## What Changes

- В колонке «Эпики команды» над списком добавляются три фильтра: «Год», «Квартал», «Тип эпика».
- В каждом фильтре первым и выбранным по умолчанию пунктом является «Все» (без фильтрации по этому параметру).
- Список эпиков филируется на клиенте по всем трём фильтрам одновременно (логическое И) — без изменений на бэкенде: `GET /epics` уже возвращает `year`, `quarter`, `type` в составе каждого эпика (подтверждено чтением кода `internal/transport/httpServer/handlers/gantt.go`), новых бэкенд-эндпоинтов/параметров не требуется.
- Список значений фильтра «Год» строится динамически из фактически присутствующих в загруженном списке эпиков команды годов (не хардкодится диапазоном лет).
- Фильтр «Квартал» — фиксированный список Q1–Q4 (как в существующей форме редактирования эпика). Фильтр «Тип эпика» — фиксированный список `feature`/`architecture`/`techdebt` с теми же подписями, что и в форме редактирования эпика («Feature»/«Architecture»/«Techdebt»).

## Capabilities

### New Capabilities
- `epic-list-filters`: фильтрация списка эпиков команды на панели скоринга по году, кварталу и типу эпика.

## Impact

- **Frontend only**: `web/gantt/js/scoring-panel.js` — рендер колонки «Эпики команды» (`renderEpicsList`, вызывается из `loadScoringEpics`). Бэкенд не затрагивается — все нужные поля (`year`, `quarter`, `type`) уже отдаются существующим эндпоинтом `GET /epics`.
