# UX-постановка для фронтенда (задача 4.1)

Составлена субагентом `ux` (код не пишет). Реализуется задачами 5.1–5.3.

## Находки, влияющие на реализацию

**Два серверных сообщения уйдут пользователю по-английски.** `schedule_settings.go:28,95`
отдают `"team not found"` и `"failed to update schedule settings"`. `handleApiError`
(`utils.js:183-194`) показывает сырой текст, если строки нет в `KNOWN_ERROR_MESSAGES` —
а её там нет. Обе строки надо добавить.

**Клиент не знает, админ ли он именно этой команды.** Фронтенд хранит только глобальную
роль, а бэкенд для `PUT` дополнительно проверяет `IsTeamAdminOf` конкретной команды. Значит
админ чужой команды увидит рабочий чекбокс и получит `403` при сохранении. Это не новый
дефект — так же работают `btn-generate` и `btn-reorder-*` (`app.js:114-122`), которые
скрываются только по `role === 'member'`. Закладываем то же поведение ради консистентности,
но требуем понятный текст на этот случай.

**Готового компонента «переключатель настройки» в дизайн-системе нет** — есть только
`.checkbox-item` (списки ролей в формах). Переиспользуем его, новый визуальный компонент не
изобретаем.

## 1. Размещение

Новый третий ряд `.toolbar-row` внутри `.toolbar-left` вкладки «Гант», после
`toolbar-row-actions` (`index.html` ~155). **Не в `toolbar-right`**: там живут переключатель
масштаба и счётчик задач — они ничего не меняют в данных, а эта настройка меняет реальные
даты всей команды.

```html
<div class="toolbar-row toolbar-row-settings">
    <div class="team-setting" id="backfill-setting">
        <label class="checkbox-item" for="backfill-block-past-toggle">
            <input type="checkbox" id="backfill-block-past-toggle" disabled>
            <span>Не начинать задачи раньше сегодняшней даты</span>
        </label>
        <span class="team-setting-hint">Настройка команды: действует на всё расписание и пересчитывает даты всех задач.</span>
    </div>
</div>
```

`.team-setting` в `components.css` рядом с блоком `.checkbox-item` (~1120):

```css
.team-setting {
    background: var(--bg-tertiary);
    border: 1px solid var(--border-color);
    border-radius: var(--border-radius-sm);
    padding: 8px 12px;
    display: flex;
    align-items: center;
    gap: 12px;
    flex-wrap: wrap;
    min-height: var(--tap-target-min);
}
.team-setting-hint {
    color: var(--text-muted);
    font-size: var(--font-size-xs);
}
```

Бордер и `--bg-tertiary` — та же визуальная лексика, что у `.view-modes`, но отдельный блок,
чтобы не читаться как ещё один переключатель масштаба. `min-height: var(--tap-target-min)`
(44px, `variables.css:127`) — у `.checkbox-item` тач-цель всего 24px, для тач-устройств мало;
поднимаем высоту только у этой обёртки, `.checkbox-item` в формах не трогаем.

Сам чекбокс и `<label class="checkbox-item">` переиспользуются как есть
(`components.css:1068-1120`), новых правил для них не создавать.

`.toolbar-row-settings` не требует правил в `responsive.css`: `.toolbar-row` уже даёт
`flex-direction: column` и `width: 100%` на `≤768px` (`responsive.css:178-187`). Проверить,
что на узком экране блок растягивается и подпись не обрезается.

## 2. Формулировки

Текст у чекбокса: **«Не начинать задачи раньше сегодняшней даты»** — описывает наблюдаемый
эффект, а не механизм. Слова «промежуток» и «простой» в интерфейс не выносятся.

Подпись-пояснение, видима всегда: **«Настройка команды: действует на всё расписание и
пересчитывает даты всех задач.»** — пользователь заранее знает, что это не локальный фильтр,
а операция над данными всей команды.

## 3. Подтверждение пересчёта — без модалки

Блокирующее подтверждение не добавляем. Действие обратимое, ничего не удаляет — в отличие от
«Перегенерации квартала» (`app.js:364-424`), которая безвозвратно удаляет и пересоздаёт
задачи и потому обоснованно требует подтверждения. Reorder-действия тоже двигают даты без
модалки — тот же уровень риска, тот же паттерн.

Вместо модалки — тост после успешного `PUT`, использующий `count`:

```js
showToast(`Расписание пересчитано: обновлено задач — ${count}`, count > 0 ? 'success' : 'info');
```

При `count === 0` текст «Расписание пересчитано: изменений не потребовалось», тип `info` —
отличимо от успешного изменения, но не выглядит ошибкой.

## 4. Доступность значения по ролям

Значение читается для **любой** роли (`GET` доступен всем аутентифицированным): чекбокс
всегда показывает актуальное состояние, даже тому, кто не может его менять. Это сознательное
отличие от паттерна `btn-generate`/`btn-reorder-*`, которые для `member` скрываются целиком:
там кнопки — разовые действия без состояния, здесь чекбокс несёт значение, объясняющее, почему
задачи на диаграмме стоят именно так. Прятать его от `member` нельзя.

Для `role === 'member'`: чекбокс **не скрывается**, а получает `disabled` после загрузки
значения; рядом добавляется вторая строка того же стиля — **«Менять может только
администратор команды.»**

Для `admin`/`superadmin`, не являющегося админом этой команды: чекбокс активен (клиент не знает
team-scoped статуса), отказ обрабатывается как ошибка сохранения — см. раздел 6.

## 5. Состояния загрузки

Читать настройку в обработчике `state.subscribe('selectedTeamId', ...)` (`app.js:43-51`),
рядом с `loadEpics`/`loadTasks`.

- **Команда не выбрана** — `.toolbar-row-settings` скрыт: настройки без команды не существует.
- **Загрузка** — чекбокс `disabled`, подпись временно «Загрузка настройки…». Не показывать
  чекбокс ненажатым по умолчанию, пока значение неизвестно: иначе «загрузка» неотличима от
  «выключено».
- **Ошибка загрузки** — чекбокс скрывается, вместо него текст с кнопкой повтора, тем же
  приёмом, что `renderTableState`/`onRetry` (`utils.js:200-230`): «Не удалось загрузить
  настройку. [Повторить]». Не показывать чекбокс в невыясненном состоянии — иначе ошибка
  неотличима от реального значения.

Реализация: `apiGet('/teams/' + teamId + '/schedule-settings')`. При ошибке `handleApiError`
не вызывать — это фоновая подгрузка состояния тулбара, а не пользовательское действие;
использовать локальный `catch`, переключающий блок в состояние ошибки с `onRetry`.

## 6. Состояния сохранения

Обработчик `change` на `#backfill-block-past-toggle`:

```js
checkbox.addEventListener('change', async (e) => {
    const next = e.target.checked;
    const prevChecked = !next;
    await withSubmitLock(checkbox, async () => {
        hintEl.textContent = 'Пересчитываем расписание…';
        try {
            const result = await apiPut(`/teams/${teamId}/schedule-settings`, { backfill_block_past: next });
            hintEl.textContent = 'Настройка команды: действует на всё расписание и пересчитывает даты всех задач.';
            showToast(`Расписание пересчитано: обновлено задач — ${result.count}`, result.count > 0 ? 'success' : 'info');
            await loadTasks(teamId);
        } catch (err) {
            e.target.checked = prevChecked;
            hintEl.textContent = 'Настройка команды: действует на всё расписание и пересчитывает даты всех задач.';
            handleApiError(err, { title: 'Не удалось изменить настройку' });
        }
    });
});
```

`withSubmitLock` (`utils.js:151-166`) принимает одиночный элемент напрямую: блокирует чекбокс
на время запроса и снимает блокировку в `finally` независимо от результата.

**При ошибке чекбокс возвращается в состояние до клика**, а не остаётся в промежуточном
положении. Для `403` строки `"вы не администратор этой команды"` и `"только администратор
команды может изменять настройки расписания"` добавить в `ACTION_REQUIRED_ERRORS`
(`utils.js:57-67`) — тогда они покажутся блокирующей модалкой, а не тостом, как уже сделано
для `forbidden`/`access denied`: повторный клик ничего не изменит без вмешательства другого
администратора.

Добавить в `KNOWN_ERROR_MESSAGES` (`utils.js:41-56`):

```js
'team not found': 'Команда не найдена. Возможно, её удалили. Обновите страницу.',
'failed to update schedule settings': 'Не удалось сохранить настройку. Попробуйте ещё раз.',
```

## 7. Файлы

- `web/gantt/index.html` — новый `.toolbar-row.toolbar-row-settings`. Не трогать `id` двух
  других рядов, легенду и `toolbar-right`.
- `web/gantt/js/app.js` — функция `loadScheduleSettings(teamId)` по образцу
  `loadEpics`/`loadTasks`, вызов из подписки на `selectedTeamId`, навешивание обработчика там
  же, где остальные листенеры тулбара (`app.js:513-523`). Существующие обработчики
  `epic-select`/`gantt-year`/`gantt-quarter` не менять.
- `web/gantt/js/utils.js` — два ключа в `KNOWN_ERROR_MESSAGES`, две строки в
  `ACTION_REQUIRED_ERRORS`. Сигнатуры `showToast`/`handleApiError`/`withSubmitLock` не менять.
- `web/gantt/css/components.css` — блок `.team-setting`/`.team-setting-hint` рядом с
  `.checkbox-item`. Базовые правила `.checkbox-item`, `.select`, `.badge` не менять.
- `gantt.css` и `responsive.css` не трогать — `.toolbar-row` уже покрывает адаптивность.

## 8. Критерии приёмки

1. При выбранной команде под рядом действий виден блок с чекбоксом и пояснением, визуально
   отличимый от `.view-modes` и легенды.
2. Без выбранной команды блок не отображается.
3. До ответа `GET` чекбокс `disabled`, подпись «Загрузка настройки…»; состояние не выглядит ни
   как «включено», ни как «выключено».
4. При ошибке `GET` вместо чекбокса — текст ошибки и кнопка «Повторить», по клику запрос
   повторяется.
5. Для `member` чекбокс виден, отражает реальное значение, `disabled`, рядом текст «Менять
   может только администратор команды.»
6. Клик блокирует чекбокс на время запроса; блокировка снимается всегда, включая ветку ошибки.
7. Успешный `PUT` — чекбокс в новом положении, тост с числом из `count`, диаграмма
   перезагружается и отражает новые даты.
8. Ошибка `PUT` — чекбокс возвращается в положение до клика, показывается русский текст
   ошибки; для `403` — блокирующая модалка, а не тост; сырой `code` и английский текст
   пользователю не показываются.
9. `team not found` и `failed to update schedule settings` отображаются по-русски.
10. На `≤768px` блок растягивается на всю ширину ряда, текст переносится, горизонтального
    скролла страницы нет.
11. Высота кликабельной области `.team-setting` не менее 44px на всех брейкпоинтах.

## Решение координатора по вынесенному вопросу

`ux` вынес наверх вопрос о блокирующем подтверждении перед переключением. Принято его
предложение — модалку не добавлять, по изложенному в разделе 3 обоснованию: действие
обратимое, данные не удаляет, а соседние reorder-действия, тоже двигающие даты, подтверждения
не требуют. Если восприятие должно быть иным, добавление модалки — небольшая отдельная правка.
