## Context

См. `proposal.md` — «Why». Вкладка отчётов (`web/gantt/index.html:416-461`, `tab-content-reports`) сейчас состоит из панели фильтров (команда/год/квартал) и двух карточек-таблиц: «Вместимость и распределение эпиков» и «Квоты по типам задач» (`web/gantt/js/reports-panel.js`). Формулы расчёта нигде на странице не объясняются.

Это изменение зависит от `fix-capacity-report-raw-total`: формулы для «Итого (чд)» / «С рисками (чд)» описывают целевое (после фикса) поведение — раздельные `raw_role_scores` (сырая сумма по ролям) и `final_score` (риск-скорректированная).

## Goals / Non-Goals

**Goals:**
- Пользователь видит формулу каждого параметра отчёта сразу при открытии вкладки, без дополнительных кликов.
- Текст формул легко поддерживать в актуальном состоянии (один источник правды в разметке/JS, не дублируется в нескольких местах).

**Non-Goals:**
- Не меняется сама логика расчёта отчёта (backend не трогаем).
- Не делается интерактивный конструктор/калькулятор формул — только статичное текстовое объяснение.
- Не переносится текст формул в API-ответ — это чисто фронтенд-контент.

## Decisions

**Один блок с формулами над обеими таблицами, всегда видимый.** Разместить `<div class="admin-card">` с заголовком «Как считаются показатели» сразу после панели фильтров и перед `.reports-grid` (`web/gantt/index.html`, между строками ~441 и ~443). Внутри — два подраздела списком (`<dl>` или маркированный список): «Вместимость и распределение эпиков» и «Квоты по типам задач», каждый со своими формулами в виде `Название — формула` (например: «Итого (чд) — сумма сырых оценок эпика по ролям (без риск-фактора)»).

Альтернатива (отклонена): всплывающая подсказка (`title`/tooltip) на каждом заголовке колонки отдельно. Отклонено, т.к. пользователь явно попросил «в явном виде вверху», а не по наведению — тултипы легко не заметить, и на мобильных/тач-устройствах наведение не работает.

Альтернатива (отклонена): собирать текст формул на бэкенде и отдавать в ответе API. Отклонено — формулы не зависят от данных конкретного отчёта, это статичный текст, и добавление на бэкенд создаёт лишнюю связанность (тексту придётся синхронизироваться с UI-версткой без пользы).

**Статичный текст, захардкоженный во фронтенде** (в `index.html` либо генерируется в `reports-panel.js` при инициализации вкладки) — не привязан к данным конкретного ответа API, поэтому не нужно ничего запрашивать дополнительно.

## Risks / Trade-offs

- [Текст формул разойдётся с реальным расчётом при будущих изменениях backend-логики скоринга/квот] → зафиксировать в комментарии рядом с текстом формул ссылку на `reports.go` (какие строки реализуют расчёт), чтобы при правках было легче не забыть обновить и текст.
- [Блок формул визуально перегружает вкладку] → сделать блок компактным (мелкий шрифт, `color: var(--text-muted)`, как у остальных пояснительных подписей в проекте), без сворачивания/раскрытия — по требованию пользователя блок должен быть виден сразу.
