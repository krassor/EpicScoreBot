## Why

Модалка «Порядок эпиков команды» показывает устаревший порядок после сохранения: пользователь меняет порядок, сохраняет, открывает модалку снова — видит старый порядок (как будто ничего не сохранилось), и в списке уже накопились дубликаты «Порядок: N» у разных эпиков.

Причина найдена в коде: `openEpicReorderModal()` (`web/gantt/js/gantt-renderer.js`) читает эпики напрямую из `state.get('epics')`, не делая запрос к серверу. Этот срез состояния обновляется только функцией `loadEpics()` (при выборе команды/загрузке страницы) — `saveOrder()` после сохранения reorder вызывает только `reloadCurrentTeamTasks()` (обновляет `state.tasks` для графика), про `state.epics` не знает. Сама операция reorder на бэкенде отрабатывает корректно (график обновляется правильно) — проблема только в том, что показывает модалка при повторном открытии.

Соседние модалки этой проблемы не имеют: `openStoryReorderModal()` каждый раз делает свежий `GET /epics/{epicId}/stories`; reorder ролей использует `state.get('tasks')`, который уже обновляется после каждого reorder.

## What Changes

- `openEpicReorderModal()` становится асинхронной и при каждом открытии делает свежий `GET /epics?team_id={selectedTeamId}` (тот же эндпоинт, что уже использует `loadEpics()`), фильтрует топ-уровневые эпики (`!e.parent_epic_id`) из полученного ответа — вместо чтения `state.get('epics')`.
- Побочный эффект исправления: `saveOrder()` для эпиков сравнивает новый номер с актуальным (только что загруженным) исходным значением, а не с потенциально устаревшим — исключает молчаливый пропуск нужных PUT-запросов на сдвиг соседей при повторных открытиях модалки без перезагрузки страницы.
- **Вне скоупа (осознанно)**: уже накопившиеся в БД дубликаты `sort_order` (как на скриншоте пользователя) не переисчисляются и не чинятся этим изменением — только предотвращается их дальнейшее появление по этой причине. Пользователь может исправить текущее состояние вручную через тот же UI после фикса.
- **BREAKING**: нет.

## Capabilities

### New Capabilities
- `gantt-reorder-modal`: модалка «Порядок…» для эпиков/историй/ролей на диаграмме Ганта — отображаемый порядок всегда отражает актуальное серверное состояние при открытии.

### Modified Capabilities
(нет)

## Impact

- **Frontend only** — `web/gantt/js/gantt-renderer.js` (`openEpicReorderModal`). Бэкенд не меняется — `GET /epics?team_id=` уже существует и уже используется `loadEpics()`.
- Зависимостей не добавляется.
- **QA**: ручная проверка — сохранить новый порядок эпиков, закрыть и снова открыть модалку без перезагрузки страницы, убедиться что показан только что сохранённый порядок; повторить reorder несколько раз подряд без перезагрузки страницы.
