## Why

UX-ревью веб-интерфейса (`web/gantt/`, все экраны) выявило, что накопленные точечные доработки разошлись между собой: один и тот же класс действий обрабатывается по-разному в разных модулях. Деструктивные действия подтверждаются тремя несовместимыми способами (кастомная модалка / нативный `confirm()` / вообще без подтверждения), защита от повторной отправки формы есть в скоринге и на Ганте, но полностью отсутствует во всех восьми формах админ-панели, а ошибки бэкенда показываются то переведённым текстом в модалке, то сырым английским текстом в тосте, исчезающем через 4 секунды.

Отдельная системная причина части дефектов — коллизия дизайн-токенов: шесть ролевых цветов буквально совпадают по hex со семантическими и статусными токенами (`--color-role-qa` = `--color-epic` = `#6366f1`, `--color-role-be` = `--color-success` = `#10b981` и т.д.). Пока значения совпадают, ошибка невидима, но она уже даёт видимый дефект на Ганте — бары «эпик» и роль QA неразличимы (проверено `validate_palette.js`: ΔE 11.3 при норме ≥15, при протанопии ΔE 0.9 между «стори» и «эпиком»), — и любая правка одного набора токенов непредсказуемо сломает цвета в другом.

## What Changes

**Дизайн-система и Гант**
- Развести по значению ролевую палитру (`--color-role-*`, `--color-epic`, `--color-story`) и семантическую/статусную (`--color-success/warning/info/danger`, `--color-status-*`) — ни одной пары с одинаковым hex
- Цвет на диаграмме Ганта кодирует только роль; уровни «эпик» и «стори» выводятся из хроматической палитры в нейтральные и различаются между собой стилем заливки — двух нейтральных уровней цветом при протанопии различить нельзя (измерено ΔE 6.0)
- Заменить хардкод цветов полосы прогресса бара (7 значений в `css/gantt.css`) на токены, производные от новой палитры
- Заменить все использования `--color-role-*` не по назначению (обозначение успеха, завершённого статуса, вероятности/влияния риска, типа задачи) на корректные семантические токены
- Согласовать цвет типа задачи между таблицей квот и таблицей вместимости на вкладке «Отчёты»; категория «Architecture + Techdebt» обозначается **только текстом, без цветовой точки** (решение пользователя: агрегат двух типов нельзя честно обозначить одним цветом)
- Русифицировать попап Frappe Gantt (`Progress:`, `day/days`)

**Подтверждение деструктивных действий**
- Единый паттерн: кастомная модалка с описанием последствий для всех каскадных/необратимых действий
- Удаление истории переводится с нативного `confirm()` на модалку с явным упоминанием каскадного удаления рисков и оценок
- Снятие администратора команды получает подтверждение (сейчас выполняется по одному клику, без диалога)

**Доступность модалок**
- Все 10 существующих модалок (плюс две новые из этого change) переводятся на нативный `<dialog>` с закрытием по `Escape`, удержанием фокуса внутри модалки и возвратом фокуса на элемент-инициатор после закрытия
- `openEditRiskModal` приводится к эталонной структуре `.modal-header` / `.modal-body` / `.modal-footer`
- На экранах ≤480px порядок кнопок в футере **не переворачивается для модалок с деструктивным действием** (решение пользователя): «Отмена» читается первой, деструктивная кнопка требует осознанного движения. Для остальных модалок `column-reverse` сохраняется

**Обратная связь и состояния экранов**
- Блокировка submit-кнопки на время запроса во всех восьми формах админ-панели
- Ошибка загрузки списка пользователей больше не оставляет таблицу в вечном состоянии «Загрузка…» — показывается сообщение об ошибке с возможностью повторить
- Ошибка загрузки списка тим-админов перестаёт маскироваться под «у команды нет администраторов»
- Единый выбор канала сообщения об ошибке (модалка / тост) по значимости действия; расширение словаря человеко-понятных сообщений вместо показа сырого текста бэкенда
- `#toast-container` получает `aria-live` / `role`, чтобы уведомления анонсировались скринридером
- Экран «Доступ ограничен» получает действие («Обновить» / «Выйти») вместо тупика с ручной перезагрузкой
- `checkAuth()` перестаёт трактовать сетевой сбой как разлогин

**Базовая семантика и тач-цели**
- Один `<h1>` на документ (сейчас три, включая оба оверлея)
- `.btn-icon` — квадратная тач-цель ≥40px на всех брейкпоинтах (сейчас 32×32px, а на ≤768px правило `min-height` без `min-width` превращает круглую кнопку в овал)
- Замена оставшегося сокращения «SP» на «чд» в выпадающем списке эпиков

**Безопасность вывода**
- Общая утилита экранирования пользовательского текста и её применение везде, где названия/описания/имена интерполируются в `innerHTML` (`scoring-panel.js`, `reports-panel.js`, `ai-chat.js`)

**Косметика (P2)**
- `confirm()`/`alert()` полностью исчезают из кодовой базы
- Селектор `.modal-overlay` в `setupGanttEvents` привязывается к `#reorder-modal`
- Хардкод `rgba(239, 68, 68, 0.05)` заменяется токеном (вводится `--color-danger-bg-subtle`)
- Удаляются мёртвые правила `.btn-vote` / `.vote-options-grid`, оставшиеся от сетки Фибоначчи

Изменений API, схемы БД и доменной модели нет. **BREAKING**-изменений нет.

## Capabilities

### New Capabilities
- `web-design-tokens`: разделение ролевой и семантической палитр, различимость баров Ганта, единый цвет типа задачи между таблицами отчёта
- `web-destructive-confirm`: единый паттерн подтверждения каскадных и необратимых действий во всём веб-интерфейсе
- `web-modal-accessibility`: клавиатурная доступность модалок (`<dialog>`, `Escape`, удержание и возврат фокуса, `role`), единая структура и порядок кнопок
- `web-async-feedback`: поведение интерфейса во время и после асинхронного запроса — блокировка повторной отправки, снятие лоадера на всех ветках, различимость «пусто» и «ошибка», человеко-понятный текст ошибки, анонс уведомлений скринридером
- `web-content-escaping`: пользовательский текст отображается как текст, а не интерпретируется как разметка
- `web-ui-foundations`: базовые свойства оболочки — иерархия заголовков документа, размеры целей нажатия, единая единица измерения трудоёмкости

### Modified Capabilities
Нет. Существующие спеки описывают доменное поведение (скоринг, планировщик, отчёты, права) — их требования не меняются; этот change добавляет требования к подаче и доступности интерфейса, которые ранее нигде не были зафиксированы.

## Impact

**Область: frontend (субагент `frontend`)** — единственная область, где меняется код:
- `web/gantt/index.html` — заголовки, `aria-live`, разметка оверлеев
- `web/gantt/js/` — `scoring-panel.js`, `admin-panel.js`, `reports-panel.js`, `gantt-renderer.js`, `ai-chat.js`, `auth.js`, `app.js`, `utils.js`
- `web/gantt/css/` — `variables.css`, `components.css`, `responsive.css`, `gantt.css`

**Область: ux (субагент `ux`)** — постановка уже сформирована этим ревью; повторное ревью после реализации для проверки критериев приёмки.

**Область: qa (субагент `qa`)** — верификация критериев приёмки; проверки, поддающиеся автоматизации (единственный `<h1>`, отсутствие `confirm`/`alert`, отсутствие пар «ролевой = семантический» токен, отсутствие `--color-role-*` в семантических контекстах).

**Backend не затрагивается**: слои transport / services / repositories не меняются, новых эндпоинтов нет, формат ошибок API `{ "error": { "code": "...", "message": "..." } }` остаётся без изменений — меняется только то, как фронтенд показывает уже приходящий текст ошибки.

**Новых зависимостей нет.** `<dialog>` — нативный элемент браузера, `validate_palette.js` — инструмент проверки из скилла `dataviz`, в рантайм не попадает.
