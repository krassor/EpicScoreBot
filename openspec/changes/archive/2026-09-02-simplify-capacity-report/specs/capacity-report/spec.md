## MODIFIED Requirements

### Requirement: Явное отображение формул расчёта параметров отчёта
Вкладка отчётов SHALL показывать пользователю в явном текстовом виде формулу расчёта каждого из параметров, отображаемых в таблицах «Вместимость и распределение эпиков» и «Квоты по типам задач», без необходимости открывать код или документацию. Пояснение SHALL быть видимым сразу при открытии вкладки отчётов, не требуя дополнительных действий пользователя для его отображения.

#### Scenario: Пользователь открывает вкладку отчётов
- **WHEN** пользователь открывает вкладку «Отчёты»
- **THEN** над таблицами отчёта отображается блок текста с формулами: как считается доступная ёмкость роли (включая округление вниз до целого человеко-дня), риск-скорректированная трудоёмкость эпика по роли (включая округление вверх до целого человеко-дня), «Итого с рисками (чд)» по эпику, «Запланировано (трудоемкость)» по роли, «Разница (недо-/перепланирование)», «Целевой лимит» и «Фактический процент» по квотам

#### Scenario: Формулы соответствуют фактическому расчёту
- **WHEN** значения в таблицах отчёта получены по определённой формуле (например, «Разница» = «Доступно» − «Запланировано»)
- **THEN** текст формулы в блоке над таблицей описывает именно эту зависимость, не расходясь с фактическим расчётом на бэкенде

## ADDED Requirements

### Requirement: Матрица вместимости показывает только риск-скорректированную трудоёмкость
Таблица «Вместимость и распределение эпиков» в веб-интерфейсе, соответствующая матрица в PDF-отчёте и лист «Вместимость» в XLSX-выгрузке SHALL отображать по каждой роли и по каждому эпику ровно одну величину трудоёмкости — риск-скорректированную (итоговую). Отдельная колонка/значение «без риска» в этой матрице SHALL отсутствовать. Сырая (без риска) трудоёмкость по ролям остаётся доступна для аудита вне главной матрицы: в JSON-ответе `GET /reports/capacity` (поле `raw_role_scores`) и в листе «Эпики» XLSX-выгрузки.

#### Scenario: Одна колонка на роль в матрице
- **WHEN** пользователь просматривает матрицу вместимости в любом из трёх форматов (веб, PDF, XLSX-лист «Вместимость»)
- **THEN** для каждой роли показана ровно одна риск-скорректированная величина трудоёмкости эпика по этой роли и одна итоговая колонка на эпик с подписью «Итого с рисками (чд)», явно указывающей на риск-скорректированный характер значения, без пары «Итого/С рисками»

#### Scenario: Сырые оценки остаются доступны для аудита
- **WHEN** пользователь запрашивает JSON `GET /reports/capacity` или открывает лист «Эпики» в XLSX-выгрузке
- **THEN** сырая (без риска) трудоёмкость по ролям каждого эпика по-прежнему присутствует в ответе/файле

### Requirement: Округление трудоёмкости в отчёте о вместимости до целого дня
Каждое риск-скорректированное значение трудоёмкости, отображаемое в матрице отчёта о вместимости (ячейка эпик×роль), SHALL округляться в большую сторону до ближайшего целого числа человеко-дней перед отображением. Каждая итоговая величина отчёта (итог по эпику, «Запланировано» по роли, общий итог) SHALL вычисляться как сумма уже округлённых величин, а не как отдельно округлённая точная сумма — так что любая видимая в отчёте сумма равна сумме видимых слагаемых. Округление применяется только к отображению отчёта о вместимости и не изменяет значения `final_score`/`role_scores`, используемые для расчёта квот по типам задач и в остальной части системы.

#### Scenario: Дробная трудоёмкость роли на эпике
- **WHEN** риск-скорректированная трудоёмкость роли на конкретном эпике равна дробному числу человеко-дней (например, 0.3)
- **THEN** в отчёте отображается округлённое в большую сторону целое число (1), а не дробное значение

#### Scenario: Итог по роли равен сумме отображаемых значений по эпикам
- **WHEN** несколько эпиков квартала имеют по данной роли уже округлённые в отчёте значения трудоёмкости
- **THEN** итоговая строка «Запланировано» по этой роли равна арифметической сумме этих округлённых значений, отображаемых по эпикам

#### Scenario: Округление не влияет на расчёт квот
- **WHEN** рассчитывается фактический процент по квоте (feature / architecture+techdebt)
- **THEN** расчёт использует точные (неокруглённые) значения `final_score`, а не округлённые для отображения отчёта величины

### Requirement: Округление доступной трудоёмкости (ёмкости) в отчёте о вместимости до целого дня
Доступная трудоёмкость (ёмкость) каждой роли, отображаемая в отчёте о вместимости (веб, PDF, XLSX), SHALL округляться в меньшую сторону до ближайшего целого числа человеко-дней перед отображением. Общая доступная трудоёмкость команды, отображаемая в отчёте, SHALL вычисляться как сумма уже округлённых величин ёмкости по ролям, а не как отдельно вычисленная (и округлённая) величина по общей численности команды — так что отображаемый общий итог всегда равен сумме отображаемых слагаемых по ролям. Округление применяется только к отображению отчёта и не изменяет исходную формулу расчёта ёмкости, используемую где-либо ещё в системе.

#### Scenario: Дробная доступная трудоёмкость роли
- **WHEN** доступная трудоёмкость роли (число участников роли × 8 × 6 × 0.838) равна дробному числу человеко-дней
- **THEN** в отчёте отображается округлённое в меньшую сторону целое число человеко-дней

#### Scenario: Общая доступная трудоёмкость равна сумме округлённых значений по ролям
- **WHEN** в отчёте отображается общая доступная трудоёмкость команды за период
- **THEN** её значение равно арифметической сумме округлённых в меньшую сторону значений ёмкости по каждой роли, отображаемых в том же отчёте

#### Scenario: Участники без назначенной роли не входят в отображаемую общую ёмкость
- **WHEN** в команде есть участники, которым не назначена ни одна оценивающая роль
- **THEN** такие участники не увеличивают ни одну из ролевых величин ёмкости и, соответственно, не входят в отображаемую в отчёте общую доступную трудоёмкость команды (в отличие от прежнего расчёта, учитывавшего всех участников команды независимо от наличия роли)

### Requirement: Согласованность данных о трудоёмкости между PDF, веб-интерфейсом и XLSX
Для одних и тех же team_id/year/quarter риск-скорректированная трудоёмкость по ролям и итоговая оценка каждого эпика, отображаемые в PDF-отчёте, SHALL совпадать (с точностью до округления, см. требование об округлении) со значениями, которые показывает веб-интерфейс и XLSX-выгрузка. PDF SHALL не содержать подписей, которые называют риск-скорректированное значение «без рисков» либо иным образом описывают его как показатель, не учитывающий риск.

#### Scenario: Значения эпика одинаковы во всех форматах
- **WHEN** один и тот же эпик со сформированной итоговой оценкой отображается одновременно в веб-таблице, PDF-отчёте и XLSX-выгрузке за один team_id/year/quarter
- **THEN** риск-скорректированная трудоёмкость по каждой роли и итоговая оценка эпика в PDF совпадают с соответствующими значениями в вебе и XLSX

#### Scenario: PDF не содержит некорректной подписи «без рисков»
- **WHEN** пользователь открывает PDF-отчёт и просматривает раздел с ролевыми оценками эпика
- **THEN** ни одна подпись рядом с риск-скорректированным значением не описывает его как «без риска» или «сырое»
