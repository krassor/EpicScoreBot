## Why

Сейчас на вкладке «Гант» задачи можно сгенерировать только по одному эпику за раз: выбрать эпик в выпадающем списке, указать дату и нажать «Сгенерировать задачи». Когда команда начинает новый квартал (или сдвигается дата старта квартала), приходится вручную перебирать все эпики квартала — по каждому отдельный выбор, отдельное нажатие, отдельный полный пересчёт расписания команды. Это долго, легко пропустить эпик, а список эпиков в выпадающем списке при этом не отфильтрован по кварталу и включает эпики всех периодов.

## What Changes

- Панель инструментов вкладки «Гант» перестраивается в **два ряда**:
  - **1-й ряд** — выбор года, выбор квартала (Q1–Q4), поле даты начала (существующее `#start-date`).
  - **2-й ряд** — выбор эпика, кнопка «Сгенерировать задачи» (существующее поведение по одному эпику), кнопка «Перегенерировать квартал», а также существующие кнопки «Порядок эпиков» / «Порядок историй».
- Выбранные год и квартал **фильтруют выпадающий список эпиков** во 2-м ряду (фильтрация на клиенте, по уже отдаваемым `GET /epics` полям `year`/`quarter`). Сама диаграмма Ганта продолжает показывать все задачи команды — фильтр на её содержимое не влияет.
- Добавляется кнопка **массовой перегенерации задач всех эпиков выбранного квартала** от указанной даты. Действие необратимо (существующие задачи эпиков квартала удаляются и создаются заново), поэтому выполняется после подтверждения в модалке.
- Добавляется новый HTTP-эндпоинт `POST /api/tasks/generate-quarter` (`team_id`, `year`, `quarter`, `start_date`), который генерирует задачи по всем подходящим эпикам квартала и делает пересчёт расписания команды **один раз** в конце, а не по разу на каждый эпик.
- В массовую перегенерацию попадают только топ-эпики команды за выбранные год/квартал со статусом `SCORED`; эпики в статусах `NEW`/`SCORING` не трогаются.
- Дата из поля ввода применяется как общий «пол» (минимально возможный старт) для каждого перегенерируемого эпика — далее конвейерный планировщик (`RecalculateTeamSchedule`) выстраивает их по `sort_order`, как это уже происходит при одиночной генерации.
- Кнопка массовой перегенерации доступна на том же уровне, что и существующая генерация: скрыта для роли `member`.

## Capabilities

### New Capabilities
- `gantt-quarter-regenerate`: выбор года/квартала на вкладке «Гант», фильтрация списка эпиков по выбранному периоду и массовая перегенерация задач всех заскоренных эпиков квартала от заданной даты.

## Impact

**Backend** (субагент `backend`):
- `transport`: `internal/transport/httpServer/handlers/gantt.go` — новый обработчик `GenerateQuarterTasks`; `internal/transport/httpServer/handlers/interfaces.go` — новый метод в интерфейсе сервиса; `internal/transport/httpServer/routers/routers.go` — маршрут `POST /tasks/generate-quarter` в существующей аутентифицированной группе (рядом с `/tasks/generate`).
- `services`: `internal/gantt/ganttService.go` — новый метод `GenerateTasksForQuarter` поверх существующих `GenerateTasksForEpic`/`RecalculateTeamSchedule`.
- `repositories`: изменений не требуется — отбор эпиков квартала делается в сервисе из уже существующего `GetTeamEpicsOrdered` (интерфейс `internal/gantt/interfaces.go`), сохраняющего порядок очереди.
- Формат ошибок API не меняется.
- Схема БД, миграции и зависимости не меняются.

**Frontend** (субагент `frontend`):
- `web/gantt/index.html` — перестройка `.toolbar` вкладки Ганта в два ряда, селекты года/квартала, кнопка «Перегенерировать квартал», модалка подтверждения.
- `web/gantt/js/app.js` — состояние выбранных года/квартала, фильтрация `#epic-select`, обработчик массовой перегенерации, скрытие кнопки для `member`.
- `web/gantt/css/components.css` (и/или `gantt.css`) — вёрстка двухрядной панели инструментов, адаптив.

**QA** (субагент `qa`):
- Юнит-тесты нового метода сервиса и обработчика (`internal/gantt/`, `internal/transport/httpServer/handlers/`).

**DevOps**: не затрагивается.
