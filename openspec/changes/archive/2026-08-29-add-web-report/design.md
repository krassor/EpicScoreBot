## Context

См. `proposal.md` — мотивация. Технический контекст:

- PDF-отчёт уже существует: `internal/report/generator.go` (`Generator.GenerateReport`, Gotenberg) + `epicService.GetReportData(ctx, teamID, year, quarter)` в `internal/services/epic.go`. Сейчас вызывается только из Telegram-бота (`internal/telegram/admin_callbacks.go`), генерирует HTML-шаблон и рендерит его в PDF через Gotenberg.
- JSON-данные для вкладки «Отчёты» уже отдаёт `GanttHandler.GetCapacityReport` (`internal/transport/httpServer/handlers/reports.go`), маршрут `GET /api/gantt/reports/capacity`, защищён `myMiddleware.TelegramAuth`, без ограничения по роли (`internal/transport/httpServer/routers/routers.go`).
- Обработчик `GetCapacityReport` использует "плоский" формат ошибок `writeError` (`{"error":"msg"}`), а не стандартизированный `{"error":{"code":...,"message":...}}` — это унаследованное расхождение, менять его в рамках этой задачи не нужно (см. правило в proposal — изменение формата ошибок отдельного эндпоинта не входит в объём). Новый эндпоинт создаётся с нуля и обязан использовать стандартный формат (`writeErrorCode`, уже есть в `helpers.go`).

## Goals / Non-Goals

**Goals:**
- Дать возможность скачать PDF и XLSX отчёт по команде/году/кварталу через один HTTP-эндпоинт веб-интерфейса.
- Переиспользовать существующий PDF-генератор без изменения его шаблона/логики.
- Добавить XLSX-генератор, отражающий те же данные, что уже показывает JSON `/reports/capacity` (не создавать новую бизнес-логику расчёта вместимости/квот — использовать существующую агрегацию).

**Non-Goals:**
- Не переписывать существующий PDF-шаблон и не менять его содержимое.
- Не добавлять графики/heatmap (упоминались в устаревшем `task_frontend.md` Шаг 4, но не реализованы и не входят в объём — только табличные данные, как в текущей вкладке «Отчёты»).
- Не менять формат ошибок существующего `/reports/capacity`.
- Не вводить ограничения доступа по ролям — используется тот же уровень доступа, что и у `/reports/capacity` (любой аутентифицированный пользователь).

## Decisions

### 1. Один эндпоинт с параметром `format`, а не два отдельных маршрута
`GET /api/gantt/reports/export?team_id=&year=&quarter=&format=pdf|xlsx`. Проще на фронтенде (один паттерн URL с разным query-параметром) и на бэкенде (общая валидация team_id/year/quarter, разветвление только в теле генерации файла). Альтернатива — `/reports/export/pdf` и `/reports/export/xlsx` — отклонена как избыточное дублирование маршрутизации без выигрыша.

### 2. Переиспользование `GetReportData`/`GenerateReport` для PDF без изменений
Логика подсчёта вместимости/квот/рисков в PDF уже реализована и покрыта существующим поведением Telegram-бота. Новый HTTP-хендлер лишь вызывает `epicService.GetReportData(ctx, teamID, year, quarter)` → `report.Generator.GenerateReport(ctx, data)` и отдаёт результат как файл, вместо отправки в Telegram.

### 3. XLSX — агрегация через существующую логику `GetCapacityReport`, не через `GetReportData`
Данные для XLSX должны соответствовать тому, что пользователь уже видит в таблицах вкладки «Отчёты» (вместимость по ролям, план/факт, квоты, эпики) — то есть той же агрегации, что в `GanttHandler.GetCapacityReport`. Чтобы не дублировать код подсчёта, эта агрегация выносится во переиспользуемую функцию/метод (сервисный слой), которую используют оба хендлера: JSON-ответ `/reports/capacity` и генератор XLSX. PDF использует отдельный источник данных (`GetReportData`) осознанно — он даёт больше деталей (риски, историю) и уже проверен в проде через бота; унификация PDF и XLSX вокруг одной модели данных — потенциальный будущий рефакторинг, не в объёме этой задачи.

### 4. XLSX-библиотека: `github.com/xuri/excelize/v2`
Одобрено пользователем. Причина выбора именно этой библиотеки — де-факто стандарт в Go-экосистеме для чтения/записи XLSX, активно поддерживается, не требует внешних бинарников (в отличие от Gotenberg для PDF).

### 5. Скачивание файла на фронтенде — прямая навигация браузера, без fetch+blob
`TelegramAuth` аутентифицирует по cookie `tg_sys_auth` (см. `internal/transport/httpServer/middleware/telegram_auth.go`), а не по заголовку — cookie автоматически уходит и при обычной навигации браузера. Поэтому кнопки «Скачать PDF»/«Скачать Excel» реализуются как обычная ссылка (`<a href>` с query-параметрами team_id/year/quarter/format) или `window.location`, без необходимости fetch+blob и без особого механизма передачи авторизации.

## Risks / Trade-offs

- **[Риск] Расхождение данных PDF и XLSX/JSON**, т.к. PDF использует `GetReportData`, а XLSX/JSON — агрегацию `GetCapacityReport` (разные пути подсчёта риск-коэффициентов и вместимости) → **Митигация**: явно зафиксировано в спеке, что XLSX обязан соответствовать `/reports/capacity`, а PDF — существующему поведению бота; при реализации сверить оба пути на одинаковых тестовых данных (задача для `qa`).
- **[Trade-off] Новая зависимость `excelize`** увеличивает размер бинарника и поверхность CVE → принято осознанно, одобрено пользователем, стандартная и поддерживаемая библиотека.

## Migration Plan

Аддитивное изменение — новый эндпоинт и новые кнопки UI, ничего не удаляется и не меняет поведение существующих `/reports/capacity` или Telegram-бота. Разворачивается обычным деплоем; откат — просто откат образа/коммита, данных/миграций БД не затрагивает.
