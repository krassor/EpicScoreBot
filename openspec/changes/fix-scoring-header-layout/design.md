## Context

См. `proposal.md` — «Why». Здесь только то, что определяет подход.

Две шапки решают одну задачу двумя способами. Шапка эпика (`renderDetails`, `js/scoring-panel.js` ~458) использует классы: `.scoring-details-header` в `css/components.css` даёт `display: flex; justify-content: space-between; align-items: flex-start; flex-wrap: wrap; gap: 16px`, а `css/responsive.css` (~220-227) на ≤768px переводит её в колонку и переключает правую группу на `align-items: flex-start`. Шапка истории (`renderStoryDetailsHtml`, ~1148) повторяет ту же раскладку инлайном, но без `flex-wrap` и без адаптивного правила.

Механизм наложения: правая группа — колоночный флекс с `align-items: flex-end`. Когда её собственная минимальная ширина превышает доступную, содержимое выходит за границы контейнера, и из-за выравнивания по правому краю переполнение уходит **влево**, поверх соседней колонки. `min-width: 0` на левой колонке позволяет ей сжаться почти до нуля, поэтому визуально «съезжает» именно заголовок.

`.btn-sm` в дизайн-системе уже есть (`padding: 6px 12px; font-size: var(--font-size-xs); min-height: 30px`) и уже присвоен кнопкам обеих шапок — но следом перебит инлайновым `style`. Аналога для поля ввода и согласования с `.badge` нет.

## Goals / Non-Goals

**Goals:**
- Убрать дублирование раскладки: одна шапка — один класс, а не копия инлайном
- Дать мелким контролам общий размер из дизайн-системы, чтобы они выравнивались по построению, а не подбором
- Снять инлайн-переопределения, глушащие `.btn-sm`

**Non-Goals:**
- Переработка состава, порядка и назначения контролов — меняется раскладка и размер, не функциональность
- Сплошной вынос инлайн-стилей из `scoring-panel.js` (цвета, отступы блоков, стили таблиц) — отдельная задача, другой профиль риска
- Изменение визуального языка: тема, радиусы, тени и палитра не трогаются

## Decisions

### 1. Переиспользовать `.scoring-details-header`, а не заводить второй класс

Шапка истории получает тот же класс, что и шапка эпика. Причина: раскладка у них идентична по замыслу, и именно расхождение реализаций породило дефект — второй класс воспроизвёл бы риск разъезжания заново.

Отличия в масштабе (у истории `h3` и меньшие размеры вместо `h2` у эпика) остаются, но выражаются вложенными классами уровня, а не переопределением раскладки.

Альтернатива — оставить инлайн и дописать в него `flex-wrap: wrap`: чинит текущий симптом, но сохраняет две копии раскладки и адаптивное правило, применимое только к одной из них. Отвергнута.

### 2. Перенос группы вместо горизонтальной прокрутки или сжатия контролов

При нехватке ширины группа контролов переносится на новую строку целиком. Альтернативы:
- сжимать контролы — упирается в нечитаемые подписи («Пересчитать по формуле» не сокращается без потери смысла);
- горизонтальная прокрутка внутри шапки — прячет кнопку «Переопределить» за краем, то есть скрывает действие.

`flex-wrap: wrap` в уже существующем классе даёт нужное поведение без нового кода — это же и есть причина, по которой шапка эпика не ломается.

### 3. Размер контролов — класс-модификатор, согласованный с `.btn-sm`

Вводится класс размера для мелких контролов строки действий: те же вертикальные отступы и `min-height`, что у `.btn-sm`, плюс парный вариант для `input`, чтобы поле не было выше кнопок. `.badge` в этих строках приводится к той же высоте.

Ключевое требование — снять инлайновые `padding`/`font-size` с этих элементов: пока они есть, любой класс размера бесполезен, так как инлайн выигрывает по специфичности всегда.

Альтернатива — повысить специфичность CSS (`!important` или длинные селекторы), оставив инлайн на месте: лечит симптом ценой войны специфичности в файле, который и так страдает от инлайн-стилей. Отвергнута.

### 4. Ширина числового поля остаётся фиксированной

Поля оценки (70-80px) не растягиваются: содержимое — целое число человеко-дней, растянутое поле выглядит как поле для текста. Фиксированная ширина задаётся классом, а не инлайном.

## Risks / Trade-offs

- **Снятие инлайновых размеров в 11 местах может изменить вид блоков, не показанных на скриншотах** (таблица оценок по ролям, блок рисков) → изменение целенаправленное: эти контролы и должны стать одного размера с остальными; проверяется визуально по каждому блоку, а не только по шапке.
- **Кнопки станут крупнее** — `.btn-sm` даёт `padding: 6px 12px` против нынешних `3px 8px` / `4px 8px` → строка действий станет выше; на широком экране это запас, на узком компенсируется переносом. Если прирост окажется чрезмерным, правильный ход — поправить `.btn-sm` в дизайн-системе для всех, а не вернуть инлайн одному блоку.
- **`.scoring-details-header` применяется к шапке истории** — правило `.scoring-details-header > div:last-child` из `responsive.css` начнёт действовать и на неё; надо убедиться, что структура шапки истории совпадает по вложенности (заголовок первым, группа контролов последней), иначе селектор попадёт не туда.

## Migration Plan

Изменение целиком во фронтенде и разворачивается вместе со статикой; шагов миграции и отката данных нет. Порядок работ — в `tasks.md`: сначала классы в CSS, затем снятие инлайна в разметке, иначе промежуточное состояние будет выглядеть сломанным.
