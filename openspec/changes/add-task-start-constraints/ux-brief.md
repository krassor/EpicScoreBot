# UX-постановка для фронтенда (задача 4.1)

Составлена субагентом `ux` (код не пишет). Реализуется задачами 5.1–5.6.

## Контекст, который нужно знать до правки

- Модалка деталей — нативный `<dialog id="task-details-modal">` (`index.html:621-662`). Фокус-ловушку, `Esc` и возврат фокуса даёт браузер через `openModal`/`closeModal` — не трогать.
- Текущий порядок полей: План → Факт → Исполнитель → Прогресс → Смещение начала (последний перед футером).
- `.form-group` — колоночный флекс, дочерние `.select`/`.input` уже растягиваются на ширину контейнера. **Не давать новым полям `min-width`/`max-width`** — здесь ограничение не нужно и вредно.
- `isGanttReadOnly()` (`gantt-renderer.js:102-105`) — единый признак «редактирование недоступно». Второго не заводить.
- `withSubmitLock` уже используется в `saveTaskDetails()` — встраиваться в него, отдельный лок не создавать.
- Бэкенд отдаёт для новых ошибок **готовый русский текст**, кроме `INVALID_NOT_BEFORE_DATE` и `RESCHEDULE_FAILED` (оба английские).

## 1. Размещение

Новый `.form-group` **последним**, после смещения начала и перед футером. Не выше: это редко используемое продвинутое ограничение, а не основной ввод — тот же принцип, по которому смещение уже идёт последним.

Блок **сворачиваемый**, а не два вечно открытых списка: модалка не должна становиться длиннее для задач без ограничения, а таких будет большинство.

```html
<div class="form-group" id="task-details-constraint-group">
    <label id="task-details-constraint-label">Начать не ранее</label>
    <div class="constraint-row">
        <input type="date" id="task-details-constraint-date" class="input-date">
        <button type="button" id="task-details-constraint-date-clear" class="btn btn-secondary btn-sm">Очистить</button>
    </div>
    <div id="task-details-constraint-task-summary" class="form-help"></div>
    <button type="button" id="task-details-constraint-task-edit" class="btn btn-secondary btn-sm">Выбрать задачу…</button>
    <div id="task-details-constraint-picker" class="hidden">
        <select id="task-details-constraint-story" class="select select--truncate"></select>
        <select id="task-details-constraint-role" class="select" disabled></select>
        <button type="button" id="task-details-constraint-task-clear" class="btn btn-secondary btn-sm">Убрать ожидание задачи</button>
    </div>
    <div id="task-details-constraint-help" class="form-help"></div>
</div>
```

`.constraint-row` — новый служебный класс: `display: flex; gap: var(--space-2); align-items: center`. Остальные классы существуют.

**Приёмка:** на задаче без ограничения блок показывает пустую дату и «Ожидание задачи не задано» без открытых списков; высота модалки вырастает не больше чем на строку.

## 2. Двухшаговый выбор

Новая функция `populateStartConstraintBlock(t)` по аналогии с `populateAssigneeSelect(t)` — без кеша, грузим заново при каждом открытии.

**Один запрос решает две задачи.** `GET /tasks/{id}/start-constraint/options` даёт и список для пикера, и человекочитаемое имя уже сохранённой ссылки: найти пару `story_id`+`role_id` в ответе и взять названия. `/tasks` отдаёт только идентификаторы, отдельный запрос для имени не нужен.

Порядок:
1. Синхронно выставить дату из `t.not_before_date`.
2. Синхронно показать «Загрузка…» в сводке.
3. По ответу: ссылки нет → «Ожидание задачи не задано»; пара найдена → «Ожидает: {стори} — {роль}»; пара не найдена или `start_constraint_ref_invalid` → см. раздел 4.
4. Кнопка разворачивает пикер: заполняется список стори, список ролей пуст и заблокирован.
5. Выбор стори → заполнить роли из уже загруженного ответа, без повторного запроса.
6. Выбор роли → свернуть пикер обратно в сводку. Отдельной кнопки «Готово» не нужно — выбор роли и есть завершение шага.

**Порядок стори брать как есть.** Сервер сортирует по алфавиту, а не по очереди эпиков как на диаграмме. Не пересортировывать на клиенте — это создало бы третий, ещё менее предсказуемый порядок.

### Длина данных (пункт 9 чек-листа)

Имя стори не ограничено ни в БД, ни в форме ввода. Для проверки взять синтетическое название 100–110 символов.

Ширину закрытый список не раздувает — её держит флекс-контейнер. Но текст выбранного значения должен усекаться многоточием, а не вылезать за рамку. Нужен новый модификатор в `components.css` рядом с `.select--epic`, **без** части про `min-width`/`max-width`:

```css
.select--truncate {
    overflow: hidden;
    text-overflow: ellipsis;
    white-space: nowrap;
}
```

Плюс на `change` выставлять `select.title` с полным названием — по прецеденту `app.js:66-72`. На тач-устройствах это не единственный канал: полное название видно при раскрытии самого списка, где ширину ограничивает уже ОС.

Свёрнутую сводку проверить тем же длинным названием: это блочный текстовый узел без `nowrap`, он переносится, а кнопка «Изменить» лежит ниже в колоночном флексе и по горизонтали не сдвигается. Дополнительного CSS не требует — но подтвердить фактом, а не декларацией.

**Приёмка:** выбор стори → роли работает без перезагрузки; при названии в 90+ символов размеры модалки не меняются, текст усечён, `title` содержит полное значение.

## 3. Недоступные варианты

Сервер присылает `unavailable`/`unavailable_reason` **на уровне роли** — сама стори остаётся выбираемой, недоступна конкретная её роль. Тексты уже русские.

Вариант присутствует в списке, но:

```js
opt.disabled = true;
opt.textContent = `${role.role_name} — ${role.unavailable_reason}`;
```

Причину писать в **видимый текст**, а не только в `title`: на тач-устройствах наведения нет, и неактивный пункт без причины выглядит как случайно сломанный. `title` добавить вдобавок, для десктопа.

Стори, у которой недоступны все роли, остаётся кликабельной — пользователь увидит причины на шаге роли. Предупреждать на уровне стори не нужно: API считает недоступность только по ролям.

Добавить контраст неактивных пунктов — сейчас они неотличимы от обычных:

```css
.select option:disabled { color: var(--text-muted); }
```

**Приёмка:** текущая задача показана как «{Роль} — это и есть текущая задача» и недоступна; задача, уже ожидающая текущую, показана недоступной с текстом про цикл; обе видимы.

## 4. Недействующая ссылка

Триггер — `t.start_constraint_ref_invalid === true`. Подача тем же приёмом, что уже применён для недействующего закрепления исполнителя (`gantt-renderer.js:989-994`, предупреждающий цвет у пояснения):

```js
summary.textContent = '⚠ Ссылка на задачу недействительна — стори или роль больше не существуют';
summary.style.color = 'var(--color-warning)';
help.textContent = 'Дата (если указана) продолжает действовать. Ограничение по задаче вернётся в силу, если стори или роль появятся снова, либо замените его здесь.';
```

**Не скрывать и не сбрасывать поле даты** и не блокировать его из-за недействительной ссылки — это два независимых подблока, и спека прямо требует, чтобы дата продолжала действовать. Кнопка выбора остаётся доступной: ссылку можно заменить.

**Приёмка:** при недействующей ссылке и заданной дате — дата видна и редактируется, текст предупреждения отдельной строкой, `member` видит тот же текст.

## 5. Индикация на диаграмме

Три существующих состояния уже заняли позиции: галочка завершения — середина справа, предупреждение о закреплении — середина слева, факт-маркер — над баром на дата-зависимой позиции. Заливка занята цветом роли.

**Четвёртая иконка — верхний левый угол бара** (`x+6, y-6`), отдельным SVG-элементом, как остальные три. Не модификация обводки — благодаря этому свободно комбинируется с индикацией отсутствия исполнителя и недействующего закрепления.

```js
const hasConstraint = !t.is_parent && (t.not_before_date || (t.wait_for_story_id && t.wait_for_role_id));
if (hasConstraint && !isTaskCompleted(t)) {
    wrapper.classList.add('gantt-start-constrained');
    // <text class="gantt-start-constraint-icon" x=x+6 y=y-6 text-anchor="start">⏳</text>
}
```

Не показывать на завершённых — тот же принцип, что уже применён к индикации отсутствия исполнителя через `:not(.gantt-completed)`: у закрытой задачи вопрос «почему сдвинулся старт» неактуален, галочка важнее. Это же снимает единственный реалистичный случай пересечения с факт-маркером.

```css
.gantt .gantt-start-constraint-icon {
    fill: var(--color-info);
    font-size: 11px;
    pointer-events: none;
}
```

`--color-info` — единственный статусный токен, не занятый тремя существующими состояниями. **Иконка обязательна как второй канал помимо цвета:** `--color-info` и `--text-muted` (используется для «нет исполнителя») различаются на ΔE 11.4 — ниже порога уверенного различения одним цветом.

**Попап** дополнить условной строкой по образцу существующей строки состояния исполнителя: не раньше даты, и/или не раньше завершения выбранной задачи, либо предупреждение о недействительной ссылке. Если ограничения нет — строку не выводить вовсе (как факт-маркер, а не как строку исполнителя, которая выводится всегда).

**Приёмка:** незавершённая задача с ограничением отличима иконкой; на завершённых иконки нет; положение существующих иконок не изменилось; в попапе видна причина.

## 6. Роль `member`

**Осознанное отличие от прецедента исполнителя.** Блок исполнителя для `member` скрывается целиком. Здесь спека требует обратного: значение видно, скрывается только управление.

```js
const editable = !isGanttReadOnly();
dateInput.disabled = !editable;
dateClearBtn.classList.toggle('hidden', !editable);
taskEditBtn.classList.toggle('hidden', !editable);
// сводка и пояснение видны всегда
```

**Приёмка:** под `member` видны и дата, и текст про ожидаемую задачу, включая признак недействительности; поле даты `disabled`, кнопки не отображаются.

## 7. Тексты отказа

Недоступные варианты уже помечены в списке, поэтому сработавший отказ сервера — это защита от гонки, а не основной путь. Пять кодов (`START_CONSTRAINT_CYCLE`, `INCOMPLETE_TASK_REFERENCE`, `TASK_REFERENCE_CROSS_TEAM`, `START_CONSTRAINT_NOT_ALLOWED_ON_PARENT`, `FORBIDDEN`) сервер отдаёт уже по-русски — записи в словарь не нужны, `handleApiError` покажет как есть.

**Добавить в `KNOWN_ERROR_MESSAGES`** только два английских:

```js
'invalid not_before_date, expected YYYY-MM-DD': 'Дата указана в неверном формате.',
'failed to set task start constraint': 'Не удалось сохранить ограничение. Попробуйте ещё раз.',
```

**Приёмка:** ни один текст на экране не содержит английских слов, кода ошибки или сырого JSON; отказ из-за гонки не роняет модалку — она остаётся открытой, список перезагружается.

## 8. Загрузка и ошибки списка

- **Загрузка:** сводка → «Загрузка…», кнопка выбора временно заблокирована.
- **Ошибка:** «Не удалось загрузить список задач для выбора» плюс кнопка «Повторить» — тот же словарь текста и кнопки, что даёт `renderTableState` для таблиц. **Поле даты при этом остаётся полностью рабочим**: ошибка загрузки списка не должна блокировать сохранение даты.
- **Гонка:** обязательна проверка `currentDetailsTaskId !== t.id` перед применением ответа — тем же приёмом, что уже есть в `populateAssigneeSelect` (`gantt-renderer.js:951, 959`). Иначе ответ по предыдущей задаче перезапишет уже открытую.
- **Пусто:** «В команде нет других задач для выбора», кнопка выбора неактивна.

**Приёмка:** обрыв сети не блокирует поле даты; переоткрытие модалки на другую задачу до завершения запроса не показывает чужие данные; «Повторить» повторяет запрос без перезагрузки страницы.

## Мобильный Telegram WebApp — обязательная проверка

На `≤768px` модалка становится нижним листом, прокрутка внутри уже работает. Свёрнутый вид пикира (раздел 1) снимает риск «два списка не помещаются», который был бы реальным при вечно открытых списках.

На `≤480px` проверить отдельно, что `.constraint-row` не сжимает поле даты до нечитаемого; при необходимости:

```css
@media (max-width: 480px) {
    .constraint-row { flex-direction: column; align-items: stretch; }
}
```

Кнопки лежат внутри тела модалки, а не футера, поэтому правило перевода футера в колонку их не затрагивает. Тач-цель `.btn-sm` на мобильных уже 36px.

**Приёмка:** на 375px поле даты, обе кнопки и сводка читаются без горизонтальной прокрутки; при разворачивании пикера оба списка умещаются по ширине листа.

## Вынесено на решение пользователя

Порядок стори в выдаче вариантов — алфавитный, а не по очереди эпиков как на диаграмме (`ganttService.go:1559`). Пользователь, ищущий стори «как на Ганте», не найдёт её на той же позиции. Поведение бэкенда уже реализовано и покрыто тестами; исправление — пересортировка в одной функции.
