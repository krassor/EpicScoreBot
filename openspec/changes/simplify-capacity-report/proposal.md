## Why

Отчёт о вместимости команды за квартал (веб-таблица, PDF, XLSX) сейчас плохо читается: главная матрица «эпики × роли» показывает две колонки-итога на эпик («Итого (чд)» и «С рисками (чд)»), различие которых понятно только по отдельному текстовому блоку формул, а не из самой таблицы. Дополнительно обнаружено, что PDF-отчёт (используется и Telegram-ботом, и веб-выгрузкой) считает эти данные по отдельному, не обновлённому в рамках `fix-capacity-report-raw-total` пути (`GetReportData`) — там обе колонки фактически показывают одно и то же риск-скорректированное число, а строка карточки эпика подписана «Сумма оценок (без рисков)», хотя значение уже учитывает риск. Раз для оценки вместимости команды имеют значение только итоговые (риск-скорректированные) цифры, а минимальный дискрет планирования — 1 человеко-день, отчёт стоит упростить и сделать по-настоящему одинаковым во всех трёх форматах.

## What Changes

- Главная матрица «эпики × роли» — в веб-таблице, PDF и листе «Вместимость» XLSX — показывает только риск-скорректированную трудоёмкость: одна колонка на роль, одна итоговая колонка «Итого (чд)» на эпик. Пара колонок «Итого/С рисками» убирается.
- Сырая (до риска) трудоёмкость по ролям остаётся доступна для аудита в JSON-ответе `GET /reports/capacity` (поле `raw_role_scores`) и в листе «Эпики» XLSX-выгрузки — из главной матрицы просто убирается.
- В PDF-карточке эпика подпись «Сумма оценок (без рисков)» переименовывается в корректную (значение риск-скорректированное) — без изменения структуры карточки, таблицы рисков и SVG-диаграмм.
- **BREAKING (внутренне, не для внешних потребителей API)**: PDF-генератор (`internal/report`, шаблон `config/template.html`) переводится на общее ядро агрегации `services.BuildCapacityReport` (`CapacityReportResponse`) вместо собственного пути `GetReportData`/`ReportData`; PDF-специфичные данные (риски по эпику, SVG-диаграммы) оборачивают общее ядро сверху. JSON-контракт `GET /reports/capacity` и XLSX-выгрузка не меняются.
- Каждое риск-скорректированное значение трудоёмкости в матрице (ячейка эпик×роль) округляется вверх до целого человеко-дня перед отображением; все итоговые суммы в отчёте (по эпику, по роли, общий итог) вычисляются как сумма уже округлённых величин — так любая видимая в отчёте сумма сходится с видимыми слагаемыми. Округление затрагивает только отображение отчёта, не значения `final_score`/`role_scores`, используемые для расчёта квот и в остальной бизнес-логике скоринга.
- Текстовый блок формул на вкладке «Отчёты» обновляется под новый набор колонок (без пары «Итого/С рисками», с упоминанием округления вверх).

### Modified Capabilities
- `capacity-report`: главная матрица отчёта о вместимости (веб/PDF/XLSX) показывает только риск-скорректированные, округлённые вверх значения; PDF использует то же ядро агрегации, что веб и XLSX, и больше не расходится с ними по числам; блок формул обновлён под новый набор колонок.

## Impact

- **Backend (services/report)**: `internal/services` — эндпоинт-агрегация `BuildCapacityReport` используется PDF-генератором; `internal/report` — `generator.go`/`types.go` переводятся на общее ядро, добавляется PDF-обёртка с рисками по эпику; `internal/report/xlsx_generator.go` — колонки матрицы переключаются на `role_scores`; округление вверх и суммирование округлённых величин — новая функция форматирования отчёта (backend, используется и веб-JSON-рендерингом на фронте, и XLSX, и PDF-шаблоном).
- **Frontend**: `web/gantt/js/reports-panel.js` (`renderCapacityTable`) — колонки по ролям переключаются на `role_scores`, убирается колонка «С рисками», округление вверх и суммирование округлённых значений на фронте синхронизировано с backend-логикой; блок формул в `web/gantt/index.html` — обновлённый текст.
- **PDF-шаблон**: `config/template.html` — матрица и подпись карточки эпика.
- **QA**: тесты на консистентность данных между JSON/XLSX/PDF для одного team_id/year/quarter, тесты на округление (включая случай суммирования округлённых величин).
- **API-контракт**: не меняется (JSON `GET /reports/capacity` как был).
