## Why

Пока скоринг стори/эпика ещё идёт (статус `SCORING`), единственный способ получить оценку по роли — чтобы каждый участник этой роли лично проголосовал (сам или через админа, который вводит оценку за каждого по отдельности в таблице «Оценки участников»). Если у администратора уже есть экспертная оценка по роли целиком (например, получена вне системы, без необходимости опрашивать каждого участника), сейчас нет способа применить её сразу ко всей роли — приходится вручную вписывать одно и то же число за каждого участника этой роли поодиночке.

## What Changes

- В таблице «Оценки по ролям» на панели скоринга, пока стори/эпик в статусе `SCORING`, для каждой оцениваемой роли эпика добавляется поле ввода и кнопка «Оценить всей ролью» (рядом с уже существующим переопределением, доступным только после `SCORED`, — это отдельный, новый механизм для активной фазы скоринга).
- По нажатию кнопки система проставляет ОДИНАКОВУЮ оценку от имени каждого участника команды с этой ролью — переиспользуя существующий механизм голосования "админ голосует за участника" (`epic_scores`, upsert по `(epic_id, user_id)`), просто применяя его сразу ко всем участникам роли одним действием, а не по одному. Уже поданные личные голоса участников этой роли перезаписываются.
- После проставления оценок автоматически запускается уже существующая проверка завершения скоринга (`TryCompleteEpicScoring`) — если это было последнее недостающее условие, стори/эпик переходит в `SCORED` как обычно. Логика подсчёта ожидаемых/поданных голосов не меняется.
- Действие необратимо перезаписывает существующие личные голоса участников этой роли — перед применением показывается подтверждение.

## Capabilities

### New Capabilities
- `role-expert-vote`: массовое проставление экспертной оценки по роли для всех участников этой роли в команде, пока скоринг ещё идёт (статус `SCORING`).

## Impact

- **Backend**: `internal/scoring/scoring.go` (новый метод сервиса, переиспользующий существующие `repo.GetUsersByTeamIDAndRoleID`, `repo.CreateEpicScore`, `s.TryCompleteEpicScoring` — без изменений в этих существующих методах), `internal/transport/httpServer/handlers/admin_scores.go` (новый хендлер), `internal/transport/httpServer/routers/routers.go` (новый роут в существующей admin-only группе).
- **Frontend**: `web/gantt/js/scoring-panel.js` — таблица «Оценки по ролям» должна во время `SCORING` строить список ролей из `evaluating_role_ids` эпика (а не из `GET /epics/{id}/role-scores`, который до завершения скоринга пуст), добавить UI ввода + кнопку + подтверждение перезаписи.
- Новый API-эндпоинт и изменение источника данных для существующей таблицы — требуется согласование перед реализацией (`/opsx:apply`).
