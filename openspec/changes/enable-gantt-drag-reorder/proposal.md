## Why

Сейчас переставить эпик или стори в очереди конвейерного планировщика можно только через модалку «Порядок…»: клик по родительскому бару → открывается список дочерних элементов → drag внутри этого списка (визуально не привязан к таймлайну) → Save. Даты на самом графике при этом менять нельзя вовсе (`readonly_dates: true`) — библиотека (Frappe Gantt, уже используется, MIT) поддерживает плавный drag «из коробки», но эта возможность выключена. Плюс любое обновление задач полностью пересоздаёт график (`container.innerHTML=''` + `new Gantt(...)`) вместо инкрементального `refresh()`. В сумме — тяжёлая, непрямая интеракция без визуальной связи с таймлайном, которая и воспринимается как «тормоза».

## What Changes

- Drag эпиков и историй **прямо на графике** (родительские бары) — перетаскивание бара по горизонтали переинтерпретируется как reorder среди тех же соседей (той же команды для эпиков, того же родительского эпика для историй), а не как буквальное изменение дат. Даты по-прежнему полностью считает бэкенд.
- На отпускании бара — сравнение новой позиции с соседями (по аналогии с уже существующей Y-координатной логикой в модалке, но по X) → вычисление новых `sort_order` для всех сдвинутых соседей → последовательные `PUT /epics/{id}/reorder` / `PUT /stories/{id}/reorder` (существующие эндпоинты, без изменений).
- Листовые ролевые задачи (бары третьего уровня) **не драгаются** — по клику как и раньше открывается модалка деталей (% выполнения, offset). Это осознанное ограничение первой итерации.
- Обновление графика после reorder переводится с полного пересоздания (`container.innerHTML='' + new Gantt()`) на инкрементальный `gantt.refresh()`/`update_task()` — устраняет источник лагов независимо от самого drag.
- Модалки «Порядок…» не удаляются — drag на графике становится дополнительным, более быстрым путём для того же действия.
- **BREAKING**: нет (чисто аддитивное изменение UX, API не меняется).

## Capabilities

### New Capabilities
- `gantt-drag-reorder`: перетаскивание эпиков и историй на диаграмме Ганта как способ изменить их порядок в очереди конвейерного планировщика.

### Modified Capabilities
(нет)

## Impact

- **Frontend only** — `web/gantt/js/gantt-renderer.js` (`renderGantt`, конфиг Frappe Gantt, `on_date_change`/`on_after_date_change`, рендер). Бэкенд не меняется: `ReorderEpic`/`ReorderStory` (`internal/gantt/ganttService.go`, `internal/transport/httpServer/handlers/gantt.go`) уже реализуют нужную семантику.
- Зависимостей не добавляется — используется уже подключённый Frappe Gantt 1.2.2 (CDN).
- **QA**: ручная/frontend-проверка (drag эпика/стори в разных позициях очереди, включая edge-кейсы — единственный элемент, крайние позиции, попытка драга ролевой задачи).
