## Context

Мотивация — в proposal.md. Текущее состояние, которое определяет подход:

- Начертание подписей задано в `web/gantt/css/gantt.css` литералами в пяти правилах: `.bar-label` 600, `.bar-label.big` 600, `.gantt-epic .bar-label` 700, `.gantt-story .bar-label` 600; контур `.bar-label-outline` — `stroke-width: 3px`.
- Те же правила продублированы в `web/gantt/js/gantt-image-export.js` (`buildStyleText()`): встроенный в картинку стиль переписан блоками из `gantt.css` и из CSS Frappe Gantt. Токены для картинки разворачиваются в литералы через `TOKEN_NAMES` + `getComputedStyle(document.documentElement)`.
- Копию-контур (`.bar-label-outline`) создаёт `applyPostRenderEnhancements` в `gantt-renderer.js`; `font-weight` она берёт инлайном из computed style оригинала, толщину обводки — из CSS-класса.
- Шрифт экрана — Inter из Google Fonts с весами 400/500/600/700. В картинке внешние шрифты недоступны (требование `gantt-chart-image-export`), там действует `Helvetica, Arial, sans-serif`.
- Выделение подписи устроено приёмом «две копии текста» из `fix-gantt-telegram-rendering` (design.md, Решение 2): он не зависит от поддержки `paint-order` в Telegram WebApp и в этой заявке не меняется.

## Goals / Non-Goals

**Goals:**
- Один источник значений для экрана и картинки, чтобы дальнейшая подстройка веса была правкой одной строки.
- Сохранить разницу начертаний «эпик жирнее истории и задачи».

**Non-Goals:**
- Смена гарнитуры, размеров подписей, цветов заливки и контура.
- Подключение новых весов шрифта (300 и тоньше).
- Страница Ганта в PDF-отчёте.

## Decisions

### Решение 1. Значения — CSS custom properties в `gantt.css`

Вводятся три токена рядом с остальными переопределениями темы Frappe Gantt (`--g-*`) в `gantt.css`:

| Токен | Значение | Где используется |
|---|---|---|
| `--gantt-label-weight` | `400` | `.bar-label`, `.bar-label.big`, `.gantt-story .bar-label` |
| `--gantt-label-weight-epic` | `500` | `.gantt-epic .bar-label` |
| `--gantt-label-outline-width` | `2px` | `.bar-label-outline` |

Отдельного токена для истории нет: по решению пользователя история и ролевая задача набираются одинаково, и третий токен без третьего значения только запутал бы подстройку. Правило `.gantt-story .bar-label` сохраняет свой `font-size: 12px` и ссылается на общий токен.

Альтернатива — просто заменить литералы в обоих файлах. Отклонена: правка вида подписей в двух местах уже приводила к расхождению экрана и картинки (находка 3.1a в `fix-gantt-telegram-rendering`), а заявка по сути экспериментальная и почти наверняка потребует ещё одной-двух подстроек.

Альтернатива — токены в `variables.css`. Отклонена: там живут токены всего интерфейса, а эти относятся только к диаграмме — как и уже лежащие в `gantt.css` `--g-*`.

### Решение 2. Картинка читает те же токены

Три новых имени добавляются в `TOKEN_NAMES` в `gantt-image-export.js`, а соответствующие правила в `buildStyleText()` переводятся с литералов на `var(--gantt-label-*)`. Механизм разворачивания токенов уже есть, так что новой логики не требуется.

Базовое правило Frappe `.gantt .bar-label { … font-weight: 400 }` в `buildStyleText()` (скопировано из библиотеки) не трогается — оно переопределяется правилами приложения ниже, как и на экране.

### Решение 3. `gantt-renderer.js` не меняется

Копия-контур уже берёт `font-weight` из computed style оригинала, поэтому новый вес доходит до неё автоматически, а толщину обводки она получает из класса `.bar-label-outline`, который переводится на токен. Правка в JS не нужна; реализация обязана это проверить, а не предполагать (см. tasks.md).

### Решение 4. Эпик 500, а не 600

Пользователь выбрал «обычный вес» — 400 для истории и задачи. Эпик сохраняет одну ступень разницы (500). Разница 400 → 500 у Inter заметна, но меньше прежней 600 → 700; если на реальной диаграмме уровни окажутся трудноотличимы, подстройка — одно значение `--gantt-label-weight-epic` (например, 600), без изменения спеки: она требует «заметно жирнее», а не конкретных чисел.

## Risks / Trade-offs

- [Тонкий светлый глиф на светлых барах эпика и истории теряет читаемость, особенно на мобильных экранах с субпиксельным сглаживанием в Telegram WebApp] → Проверка на всех шести ролевых заливках и на барах эпика и истории в обоих окружениях (tasks.md, раздел 3). Если просядет — сначала вернуть контур к 3px (токен), затем поднять вес до 500; оба шага — правка токена.
- [Контур 2px слабее отделяет текст от бара, чем 3px] → Цветовой контраст текста и бара не меняется, меняется только ширина обводки; оценивается визуально в той же проверке. Требование «Подписи задач читаемы в основном клиенте» из активной заявки `fix-gantt-telegram-rendering` остаётся в силе и проверяется тем же сценарием.
- [В картинке (Helvetica/Arial) разница 400/500 может быть менее выражена, чем у Inter: у Arial нет промежуточного веса 500, и браузер рисует его как 400] → Эпик в картинке может выглядеть так же, как история. Это расходится с требованием «Подпись эпика жирнее». Проверяется отдельной задачей; при подтверждении — `--gantt-label-weight-epic: 600` (у Arial 600 рисуется полужирным) либо отдельное значение для картинки. Решение принимается по факту на выгруженной картинке.
- [Экспериментальный характер] → Откат — вернуть три значения токенов к 600/700/3px; структура остаётся.

## Migration Plan

Только статика фронтенда, выкатывается обычным релизом. Откат — новый релиз с прежними значениями токенов; данные и контракты не затрагиваются.
